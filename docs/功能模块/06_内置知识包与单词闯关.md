# 模块 06 · 内置知识包与单词闯关

> 目标：让「没有自己的资料」的新用户也能立刻开始 —— 内置英语语法专题与四/六级词库，
> 并用闯关把背单词变成可持续的动作。答错的词直接进入复习队列，复用 M1 的 SRS 调度。

---

## 一、数据来源与编译

原始素材放在仓库根目录 `data/英语/`：

```
data/英语/
├── 单词/大学英语四级词汇-乱序版-答案.pdf   （296 页）
├── 单词/大学英语六级词汇-乱序版-答案.pdf
└── 语法/**/*.md                            （50 篇，按语法点分目录）
```

编译命令（在 `frontend/` 下执行，可重复跑）：

```bash
npm run build:packs
```

脚本 `scripts/build-packs.mjs` 做三件事：

| 步骤 | 说明 |
| --- | --- |
| PDF 解析 | 用 `pdfjs-dist` 读取文本片段，**按表头（序号/单词/音标/释义）动态识别列边界**，再按最近的序号行聚合为词条；两本 PDF 的列坐标相差约 8pt，硬编码阈值会串列 |
| 释义清洗 | 去掉「人名/地名」等考试无关义项，超长截断到 150 字 |
| 语法归集 | 遍历 `语法/` 目录，取一级标题为标题、目录名为分类，按分类 + 文件名排序 |

产物（提交到仓库，部署时直接静态托管）：

```
frontend/public/packs/
├── index.json      { version, generatedAt, packs: [{id, kind, title, count, bytes, file}] }
├── cet4.json       4424 词，约 510 KB
├── cet6.json       5518 词，约 628 KB
└── grammar.json    50 篇，约 344 KB
```

词条结构（键名压缩以减小体积）：

```ts
{ "w": "punctual", "p": "/ˈpʌŋktʃuəl/", "m": "adj. 准时的，守时的；精确的" }
```

> 加载器 `src/services/knowledgePack.ts` 运行时 `fetch(BASE_URL + packs/xxx.json)`，
> 并做内存缓存。**不进主 bundle**，避免拖慢首屏。

## 二、单词闯关（`/study/play/quest`）

### 2.1 规则

| 项 | 规则 |
| --- | --- |
| 每组 | 10 题，4 选 1（正确释义 + 3 个同库干扰项） |
| 生命 | 3 条，答错 -1，归零即结束 |
| 计分 | 答对 `10 + min(10, 连击 × 2)` |
| 显示 | 选项只显示**短释义**（首个分号/逗号前，≤24 字），完整释义用于入队与结果页 |
| 进度 | 最高分与局数存 `localStorage: knowflow.quest.progress` |

纯逻辑在 `src/services/quest/engine.ts`（`buildQuestions / answerCurrent / nextQuestion / accuracy`），
不依赖 DOM 与数据库，可单测；随机源可注入（`rng`）以便复现。

### 2.2 答错即入队

`src/services/quest/wordCards.ts`：

1. 首次进入时创建分类「英语」与资料「四级/六级词汇（闯关错词）」，作为卡片容器（便于学习中心回溯来源）
2. 错词若已有同名卡片 → 重置为「不熟悉」；否则新建卡片
3. 统一走 `markMastery(id, 0)`：10 分钟后重新出现，直接进入「今日复习」

这样「玩」和「学」共用同一套记忆调度，而不是两套割裂的系统。

---

### 2.3 单词学习页（`/study/words`）

闯关是「撞见」，还需要一个能主动翻阅的地方——4424 / 5518 个词，不能只靠答题时随机出现。

| 项 | 说明 |
| --- | --- |
| 词库 | 四级 / 六级切换，按字母排序（原始包是乱序版，浏览时重排） |
| 筛选 | 搜索（单词或释义）+ A-Z 首字母；输入关键词会自动清掉首字母，避免两个条件「与」成 0 结果 |
| 列表 | **窗口化渲染**：行高固定 68px，只渲染视口附近 ±4 行，4424 条也只有十几行 DOM |
| 操作 | 每行「加入复习」→ `addWordToReview(packId, word, false)`，进同一条 SRS 队列 |
| 统计 | 顶部显示「已加入复习 N / 总数」，按钮同步变「已加入」 |
| 入口 | 学习中心第 5 个 Tab「单词」+ 侧边栏二级项 + 概览页入口卡 |

窗口化没有引第三方库：行高固定后 `起始下标 = scrollTop / 行高`，
再用一个撑高的占位 div 加 `translateY` 把可视段顶到正确位置。

## 三、语法学习页面（`/study/grammar`）

内置的 50 篇语法不只是「导入后变成资料」，还提供独立的学习页面，入口在侧边栏「语法学习」与首页快捷操作。

| 区域 | 说明 |
| --- | --- |
| 目录栏 | 搜索框（标题 + 正文）、专题标签（默认显示前 8 个专题，其余收到 `+N`）、语法点列表（已加入的显示绿色勾） |
| 阅读区 | 标题层级、**表格**（时态对照表）、引用、列表全部按 Markdown 渲染，不再是带 `|` 的原始文本 |
| 单篇操作 | 「加入资料库」（按标题去重，分类按专题自动创建）、「生成卡片」（落库到该资料并进入复习队列） |
| 搜索排序 | 标题命中的排在前面，只在正文出现的标注「正文提及」，避免「搜虚拟却把倒装排第一」 |
| 移动端 | 首屏停在目录（`<1024px` 不自动打开第一篇），点开一篇切到正文，顶部「目录」返回 |

**Markdown 渲染**：`utils/markdown.ts` 是零依赖实现（不引入 marked/markdown-it），覆盖标题、GFM 表格、引用、列表、代码块、粗斜体、链接。要点：

- **先做块级解析、行内渲染时才转义 HTML**。如果一开始整份文本转义，引用符 `>` 会变成 `&gt;`，引用块解析直接失效（这是实现时踩到的坑）
- 行内代码先占位再处理强调，否则 `` `a * b` `` 里的 `*` 会被当成斜体
- 所有输出都经过转义，`<script>` 只会显示为文本

`pages/DocumentDetailPage.vue` 也接入了同一套渲染：正文命中 `looksLikeMarkdown()`（含标题 / 表格 / 代码块）时用富文本，普通笔记仍走原来的 `whitespace-pre-wrap` 保留换行，互不影响。

## 四、内置语法包批量导入

`pages/ImportPage.vue` 顶部有「内置知识包」卡片：

- 按 `index.json` 列出 `kind: "docs"` 的包（当前为英语语法 50 篇）
- 一键导入：按**标题去重**，分类按专题目录自动创建（定语从句 / 名词性从句 / 时态 …）
- 导入后即为普通资料，可让 AI 提炼要点、生成卡片
- 与「语法学习」页面的单篇「加入资料库」共用同一套去重与分类规则，两种入口不冲突

## 五、小工具（端内）策略

端内无网络，词库与语法包都加载不了，因此：

| 项 | 处理 |
| --- | --- |
| 路由 | `IS_MINITOOL` 时不注册 `/study/play*`、`/study/grammar`、`/study/idiom` 等依赖在线知识包的子路由（也就不会把这两个页面打进产物）；未知路径由 `/:pathMatch(.*)*` 兜底回首页 |
| 加载器 | `@/services/knowledgePack` 用 `minitool/knowledgePack.stub.ts` 替换：索引返回空、词库/语法抛「请用网页版」 |
| 入口 | 侧边栏子项、学习 Tab、首页快捷入口中的「语法学习」「成语学习」「快乐学习」端内均不渲染 |
| 产物 | `scripts/clean-minitool.mjs` 删除 `dist-minitool/packs` 与 `sw.js` |

验收：`dist-minitool` 内 `fetch(`、`getUserMedia`、`MediaRecorder` 计数均为 **0**，且无 `Quest` / `Orb` / `Grammar` chunk、无 `packs/` 目录。
