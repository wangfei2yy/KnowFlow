### 三个必须记住的解析坑

1. **成语条目有四种写法**，只按「成语：解释」匹配会漏掉一大半：
   - `韬光养晦：比喻隐藏才能`
   - `焦思苦虑解释：着急忧虑`（词条和"解释："连写）
   - `后车之戒(huchēzhījiè)对后面跟上来的车子的警戒`（带拼音）
   - `白草黄云（解释）形容边塞秋季的荒凉景象`
2. **PDF 会把多条词条塞进同一行**（`…白草黄云（解释）…`），必须先按 `词条（解释）` / `词条解释：` 做行内切分，否则长的会把后面全吞进一条（修之前最长释义 963 字）。
3. **Word 导出的换行是单独的 `\r`**，`split(/\r?\n/)` 切不开，整份文档会变成 1 行 → 一条都解析不出来。用 `/[\r\n]+/` 或 `split(/\r\n?|\n/)`。

判定收紧：只保留 **4 字成语**、释义 6~150 字，能一次性把「子里一定在盘算」这类句子碎片过滤掉。

## 三、食谱（`/kitchen`）

饮食模块独立于学习：`KitchenLayout` + 三个 Tab（食谱 / 时令 / 计划）。

- 列表：按餐次筛选（早/午/晚）+ 搜索（菜名、材料、标签）+ 标签展示

## 四、时令（`/kitchen/season`）

四季各一张卡：当季高亮 + 「当季」徽章，蔬菜（绿）与水果（黄）分开列。当前季节按月份推算（3-5 春 / 6-8 夏 / 9-11 秋 / 12-2 冬）。

## 五、饮食计划（`/kitchen/plan`）

**生成规则**（纯前端，不调 AI）：

```
忌口过滤 → 按餐次分池 → 每天早/午/晚各抽一道
        → 同餐次「最近两天不重复」→ 汇总购物清单
```

关键取舍：

- **加权随机**而不是硬性优先：带材料清单的菜权重 3，只写做法的权重 1。试过「只用有材料的菜」，午餐只剩 4 道，7 天会反复出现同样三道；加权后午餐/晚餐能做到 7/7 不重复，购物清单仍覆盖 80+ 种材料。
- **购物清单标注缺口**：概览行显示「共 N 种材料（M 道菜未列材料）」，避免用户以为清单漏了。
- **周期**：一周 7 天 / 四周 28 天，切换后自动重新生成。
- **落地**：「今日菜单加入任务」把当天三餐 + 每步做法写成一条任务，复用任务清单。

**食材构成**：购物清单下方展示「本周食材构成」——把清单材料按图鉴分类计数（蔬菜 N 种 / 肉类 M 种…）。
只数种数、不折算热量：原始菜谱只写「适量」没有份量，硬算热量是编数字。详见 [模块 09](./09_食材图鉴.md)。

**仍然没有**：热量目标、体重管理。要做这些需要带份量的食谱数据，当前数据源给不出来。

## 七、端内（小工具）策略

成语、食谱、时令都依赖在线知识包（`fetch`），端内一律不注册：

| 项 | 处理 |
| --- | --- |
| 路由 | `IS_MINITOOL` 时不注册 `/study/idiom`、`/kitchen/*` |
| Tab | 学习模块只剩「概览 / 复习」两个 |
| 侧边栏 | 无「成语学习」子项、无「饮食」一级入口 |
| 首页 | 快捷入口过滤掉语法/成语/闯关/饮食 |
| 产物 | `clean-minitool.mjs` 删除 `packs/`；未知路径由兜底路由回首页 |

验收：`dist-minitool` 内 `fetch(` = 0、无 `Idiom`/`Kitchen`/`Recipe` chunk、zip 12 文件审计 PASS。
