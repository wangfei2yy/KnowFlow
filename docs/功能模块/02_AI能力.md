# 模块 02 · AI 能力

> 让 AI 理解并加工你的资料：摘要、问答、行动项、学习卡片。
> 返回主文档：[项目说明文档](../项目说明文档.md)

---

## 一、核心 AI 能力

| 能力 | 说明 | 写入结果 |
| --- | --- | --- |
| 生成摘要 | 提炼 summary + 重点 keyPoints + 关键词 keywords | 保存到资料的摘要字段 |
| 资料问答 | 基于已保存资料回答问题，展示真实来源引用与原文片段；无证据时明确告知「没有找到足够依据」，不编造 | 仅对话展示 |
| 提取行动项 | 从会议记录、总结等文本中识别任务 | 预览确认后写入任务清单，可回溯来源资料 |
| 生成卡片 | 生成问答对，制作可复习的记忆卡片 | 预览确认后存入学习中心 |

**通用规则**：所有 AI 结果均「先预览、确认后写入」，不覆盖原始资料。

## 二、卡片生成的自定义

- **张数可自定义**：生成前可选固定张数，也支持 **「自动（AI 判断）」**——由模型根据内容密度自主决定张数（提示词建议 3~8 张），适合内容长短不一的资料
- 卡片自动关联来源资料，学习中心可按来源筛选

## 三、AI 接入方式（三种，可自由切换）

| 方式 | 是否需要 Key | Key 存放位置 | 适用场景 |
| --- | --- | --- | --- |
| 演示模式（默认） | 否 | — | 任何人打开即用，完整演示流程 |
| 自备 Key（BYOK） | 是（用户自己的） | 用户浏览器 localStorage | 线上用户无后端时，用自己的 Key 直连模型 |
| 后端代理 | 是（部署者的） | 服务端 `.env` | 面向公众的产品，Key 不下发到浏览器 |

在「设置 → AI 配置」中切换，选择「接入真实模型」后可进一步选择「后端代理」或「自备 Key」：

- **自备 Key 模式**：填写服务地址（如 `https://api.openai.com/v1`）、模型名和 API Key，浏览器直接请求模型服务。Key 只存在本机浏览器，不上传服务器；默认仅在当前会话有效（关闭浏览器自动清除），勾选「在本设备记住」才会持久化。
- **后端代理模式**：只填后端地址和模型名，Key 由服务端 `.env` 保管，浏览器完全接触不到。

### 连接测试

配置真实模型时可点 **「测试连接」** 按钮，用最小请求验证地址 / 模型 / Key 是否可用：

- 成功 → 绿色提示
- 失败 → 红色提示，并按原因给出具体说明（401 密钥无效 / 403 无权限 / 429 额度不足 / 网络不通等）

> 安全边界：BYOK 模式的 Key 存在浏览器存储，存在被本机 XSS 或共享设备读取的风险，因此产品不承诺绝对安全；若要面向公众长期运营，应使用后端代理模式。

## 四、工程健壮性

### 4.1 JSON 解析健壮化

大模型返回的 JSON 经常带脏内容（markdown 围栏、前后解说文字、对象包裹、尾随逗号）。解析器采用多层策略：

1. **括号配对提取**（extractBalanced）：从首个 `{` 或 `[` 开始按括号配对截取完整 JSON 块，而不是简单找下标切分
2. **包裹层剥离**：支持 `{"cards": [...]}` / `{"items": [...]}` / `{"tasks": [...]}` / `{"list": [...]}` 等对象包裹结构
3. **容错修复**：容忍尾随逗号
4. 解析失败时给用户友好报错「AI 返回格式异常，请重试」，而非静默失败

### 4.2 提示词约束

系统提示词中明确要求「必须只输出 JSON，不要附加任何解释文字」，降低脏输出概率。

## 卡片生成的批量与分段策略

长资料（如几十个知识点的英语语法笔记）容易出现「只提取前几个」，原因有二：内容被 12000 字截断、卡片数量上限只有 3~8 张。现已改为：

| 项 | 策略 |
| --- | --- |
| 内容处理 | **固定 2500 字一段**（优先在段落/换行/句号处切），循环逐段调用后合并；不再因资料超长而放大单段（长输入最容易让模型吐空）。超过 60 段（约 15 万字）只处理前 60 段 |
| 段数上限 | 最多 12 段；超长资料按需放大每段长度，保证覆盖全文又不至于发几十次请求 |
| 张数 | 选「自动」时按篇幅估算：约每 500 字 1 个知识点，5~60 张；也可手选 5/10/15/20/30 |
| 输出上限 | 请求带 `max_tokens`（按张数预留，1500~8000），避免模型提前截断 |
| 去重 | 按问题归一化（去空格标点、忽略大小写）去重，并过滤空卡片 |
| 容错 | 单段失败自动**二分重试**（最多 3 层，内容 <600 字不再拆）；某段彻底失败不拖垮整体 |
| 三级降级提示 | 完整提示 → 简化提示（最多 4 张）→ 逐行纯文本（`问题 ||| 答案`），弱模型也能出卡 |
| 宽松解析 | JSON 失败时按行解析，兼容 `问：…答：…`、`Q: …A: …`、代码块包裹、前后带说明文字 |
| 失败提示 | 空返回会区分原因：达到输出上限 / 内容被安全策略拦截 / 确实为空，并给出可操作建议 |
| 请求预算 | 单份资料最多 48 次模型请求（含重试），避免反复失败刷爆额度 |
| 段数上限 | 60 段（约 15 万字）；再长会 console.warn 并截断处理 |
| 进度 | 界面显示「已处理 3/4 段…」 |

对应实现：`frontend/src/services/ai/aiService.ts`（`generateCardsFromContent`）、`OpenAICompatibleProvider.generateFlashcards`。
回归测试：`npm run test:cards`。
