# 模块 05 · 数据管理与部署

> 本地优先的持久化方案、备份恢复、隐私安全与发布部署。
> 返回主文档：[项目说明文档](../项目说明文档.md)

---

## 一、本地持久化

- 数据存于浏览器 **IndexedDB**（Dexie.js），刷新、关闭浏览器均不丢失
- 主键 UUID，时间统一 ISO 8601
- 表结构：`documents` / `categories` / `tasks` / `flashcards` / `aiJobs`（见主文档「数据模型」）
- Schema 版本管理：Dexie `version(N)` 声明式升级（当前 version 2，flashcards 表含 createdAt 索引支持排序），升级自动迁移，无需手动清理数据
- 小知的好感度与对话记录存于 localStorage（轻量状态与本地库分离）

## 二、备份与恢复

- **JSON 导出**：全部资料、分类、任务、卡片一键导出为 JSON 文件
- **JSON 导入**：支持 **合并**（与现有数据共存）与 **覆盖**（清空后导入）两种模式
- 导入前展示数据概览供确认

## 三、清除数据

- 「设置 → 数据管理」提供**清除本地数据**入口
- 二次确认后执行，同时清除 IndexedDB 与 localStorage（含示例资料加载标记、小知状态）

## 四、隐私与安全

| 原则 | 落地方式 |
| --- | --- |
| 本地存储 | 资料默认保存在浏览器 IndexedDB，不上传服务器 |
| AI 授权 | 调用 AI 前告知将发送的内容，需用户主动操作 |
| 密钥保护 | 后端代理模式 Key 仅存服务端 `.env`；BYOK 模式 Key 只存用户本机浏览器 |
| 内容安全 | 用户输入按普通文本渲染，不执行资料中的 HTML/脚本 |
| 诚实声明 | 本地存储不等于加密保险箱，产品不承诺绝对安全 |

## 五、发布与部署

前端为**纯静态应用**：

1. `npm run build` 产出 `dist/`；
2. 部署到任意静态托管（WorkBuddy 发布、Vercel、Netlify、GitHub Pages 等）；
3. 已使用 **hash 路由 + 相对路径**，可部署到任意子路径，刷新不 404。

> 注意：更新部署后浏览器可能缓存旧 chunk，导致点击页面报「Failed to fetch dynamically imported module」，强刷（Ctrl+F5）即可解决。

### 5.1 必须用生产构建启动（踩过的坑）

WorkBuddy 发布默认会用 `npm run dev` 起 Vite dev server。**dev 模式上线是致命的**：
每个模块单独请求、按需转译、不打包不压缩，首屏要发几十上百个请求，词库 JSON 500 KB
也是原样传输。曾经的线上就踩了这个坑，表现为「点开要等好几秒」。

判断方法（一条命令）：

```bash
curl -s "https://<域名>/?sharecode=xxx" | grep -c "vite/client"   # 输出 1 = 还是 dev server
```

正确做法是部署时显式指定启动命令：

```bash
# 平台参数 startCmd
npm run serve:prod      # = vite build && node server.mjs
```

`server.mjs` 是只用 Node 内置模块写的静态服务器（不引入 express 等依赖）：

| 能力 | 说明 |
| --- | --- |
| br / gzip 预压缩 | 只压 >1 KB 的文本资源，结果按「路径 + mtime + 编码」缓存，不重复压 |
| 缓存头 | `/assets/*`（带内容哈希）→ 一年 immutable；`index.html` 与 `sw.js` → no-cache；`/packs/*.json` → 10 分钟 |
| 缺失资源 | `/assets/*` 不存在时返回 404，**不回退 HTML** —— 否则浏览器把 HTML 当 JS 解析，真实错误被掩盖 |
| 安全 | 路径穿越防护、`X-Content-Type-Options: nosniff`、只接受 GET/HEAD |
| 退出 | 监听 SIGTERM 后关闭连接再退出，避免平台重启时端口占用 |

### 5.2 首屏优化记录（2026-10-29）

实测口径：线上单次请求 TTFB ≈ 0.45s 是平台代理的固定开销，所以**少一跳比少 8 KB 更值**。

| 项 | 优化前 | 优化后 |
| --- | --- | --- |
| 启动方式 | vite dev（每模块一转译） | 构建产物 + gzip |
| 主包 | 308 KB 未压缩 | 317 KB → br **113 KB** |
| 首屏请求 | 主包 → 首页 chunk → pack 索引（串行） | html → **app.js + css 并行** → pack 索引 |
| 首页 chunk | 独立 3.2 KB，多等一个 RTT | 静态引入，并进主包 |
| 二次访问 | 每次导航都要走网络 | SW stale-while-revalidate，导航与资源全命中缓存 |
| 词库 | 每次进页面都重新拉（cet4 510 KB） | SW 缓存，二次进入 0 请求 |

`sw.js` 的三条策略：

- **页面导航**：先给缓存（秒开），后台拉新版本下次生效 —— 原来是网络优先，每次都要等 0.45s
- **`/assets/*`**：cache-first（文件名带内容哈希，永不过期）
- **`/packs/*.json`**：stale-while-revalidate

两个必须注意的点：只缓存 `res.ok` 的响应（否则 404 会被缓存住）；`caches.match` 一律加
`ignoreSearch`，否则 `?sharecode=` / `?pack=` 会导致永不命中。

若需真实 AI（后端代理模式），需同时部署 FastAPI 后端并配置环境变量。

### 小红书小工具（端内离线版）

小红书端内以「小工具」形式承载 H5：容器**完全不联网**、脚本必须为 classic script、禁用 Worker。项目为此单独提供了一套构建：

```bash
cd frontend
npm run build:minitool     # 产出 dist-minitool/
```

打包后的 `knowflow-minitool.zip` 可直接上传创服平台。端内为离线版（AI 走本地规则、无文件导入与备份导出），详细改造与校验结论见 [小红书小工具发布](../小红书小工具发布.md)。

## 六、本地端口约定

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| 前端开发服务器（Vite） | **5195** | 原 5173 + 22；`server.port` 优先读 `PORT` 环境变量（托管平台注入），本地回落到 5195 |
| 前端本地预览（vite preview） | **4195** | 原 4173 + 22 |
| 后端（FastAPI / uvicorn） | **8022** | 原 8000 + 22；`python run.py` 默认 8022，也支持 `APP_PORT` / `PORT` 覆盖 |
| 后端 CORS 默认允许来源 | `http://localhost:5195` | 见 `backend/.env.example` 的 `CORS_ORIGINS` |

> 线上部署无需改端口：托管平台会注入 `PORT`，Vite 配置优先采用注入值。
