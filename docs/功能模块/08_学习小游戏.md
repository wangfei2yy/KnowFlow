## 二、进度记忆

三个独立的 localStorage 域，读写全部 try/catch 静默（存不下也不能卡住这一局）。

### 2.1 闯关会话 `knowflow.quest.session`

```ts
{ [packId]: { packId, session: QuestSession, savedAt: ISO 字符串 } }
```

| 时机 | 行为 |
| --- | --- |
| 每次作答后、切到下一题后 | 写入（整份会话，只存 index 没意义，题目是每局重抽的） |
| `session.finished` | 清掉**该词库**的存档 |
| 读取 | 过滤掉「已结束 / 题目为空 / 超过 7 天」的脏数据并写回 |

按词库分开存，是为了「有 cet4 存档时切到 cet6」不会把 cet4 的半局冲掉。

`resumeSession()` 处理一个边界：用户是在「已作答、还没切下一题」的瞬间退出的，
直接恢复会卡在一道不能操作的题上，所以恢复时自动推进一格；推进后已到末尾则视为这局结束、不再恢复。

### 2.2 复习位置 `knowflow.study.position`

```ts
{ fingerprint: string, index: number }
```

`fingerprint` 是当前复习队列卡片 id 串起来的 djb2 哈希（带分隔符，避免 `["ab","c"]` 与 `["a","bc"]` 撞车）。

- 队列没变 → 停在上次那张
- 队列变了（标记掌握后队列缩短）→ 丢弃旧位置，回到第 1 张，不越界
- 只在「队列模式 + 复习视图」下记录；列表视图、临时筛选、`?mode=all` 都不写，
  免得把正常复习的位置覆盖成浏览时的位置

### 2.3 游戏成绩 `knowflow.game.progress`

```ts
{ [gameId]: { [packId]: { bestScore, plays, lastPlayedAt } } }
```

球球走这个新键，闯关沿用旧的 `knowflow.quest.progress`，两者不混。

## 三、单词球球

### 3.1 玩法

```
玩家球：写着【当前目标词的中文短义】（≤15 字，最多三行）
食物球：写着【英文单词】，按难度场上 4 / 6 / 8 / 10 个，其中恰好 1 个是正确答案
吃对  → 球 ×1.08，得分 +10（连击 +2/次，封顶 +10），换下一个目标词
吃错  → 球 ×0.88，扣 1 条命，屏幕抖动，目标词不变（还得继续找它）
结束  → 3 条命耗尽，或 60 秒倒计时归零
```

为什么玩家球放中文、食物球放英文：英文 1~3 个词放得下，中文释义动辄十几个字塞不进小圆；
反过来会两个都看不清。

### 3.2 数值表

| 项 | 值 | 说明 |
| --- | --- | --- |
| 初始半径 | 40 | 世界单位 |
| 半径上限 | **76** | 不封顶会越吃越大，判定范围（r×0.92）跟着膨胀，一口吞掉好几个球 |
| 吃对增长 | ×1.08（复利） | 从 40 长到 76 约 8 次，之后不再变大 |
| 吃错缩小 | ×0.88 | 两次吃错约退回起点 |
| 半径下限 | 24 | 防止缩没 |
| 屏幕移动速度 | **恒定 300 px/s** | 世界速度 = `300 / cameraScale(r)`，球大了不会变慢 |
| 初始命 / 时限 | 3 / 60 秒 | |
| 场上食物 | 4 / 6 / 8 / 10 个（难度档） | 吃掉后立刻补位；档位只改这个数，速度/血量/时长都不动 |
| 连击 | 连续答对 +2 分/次，最高 +10 | 答错清零 |
| 相机缩放 | `1 → CAMERA_MIN(0.75)` 线性 | r=40 → 1.0；r=76 → 0.75。可见面积只放大 1.8 倍；玩家球在屏幕上从 40px 长到 57px（成长看得见） |
| 可吃区域半径 | `(360 + r × 0.6) × √(选项/10)` | 起始 384、满级 406；相机不再大幅拉远，场地也就不必疯长，大多数球留在视野里 |

数值集中在 `src/games/orb/engine.ts` 的 `ORB` 常量里，调手感只改这里。

#### 为什么改成「半径封顶 + 相机拉远」

最初的设定是「球越吃越大，视野越大」，实际玩起来有三个问题（都来自用户反馈）：

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 一次吃到好几个球 | 吃判定是 `r × 0.92`，r 无上限；吃到 200 时判定圈盖住半屏 | 半径封顶 76，判定圈随之封顶 |
| 球占满屏幕 | 球一直长，相机再缩也追不上 | 半径封顶 76 + 相机最多退到 0.75：球在屏幕上 40 → 57px，既不会占满屏，又有「我变大了」 |
| 越玩越慢 | ①速度写成 `250/(1+r/160)`，r=76 时只剩 68%；②主循环把 dt 夹在 50ms，掉到 20fps 以下时速度被悄悄砍掉一截 | ①改成「屏幕速度恒定」：世界速度 = 300 / scale；②页面改固定步长累加 + 引擎 dt 放宽到 100ms |

于是「变大」的反馈从「球占屏幕」换成了**视野变远**，但幅度是收着的：
相机最多退到 0.75（早期版本退到 0.53），食物球的屏幕半径被 `max(24, f.r*scale)` 兜住，
所以待吃的球看起来一直一样大，参照物稳定、判断距离更容易。

#### 为什么不再把视野缩到一半（地图 / 参照物层面的取舍）

早期相机是 `40/r`，打满时缩到 0.53：一屏能看到的**世界面积是 3.6 倍**。
这带来两个问题，都是玩家能直接感受到的：

1. **参照物整体变小、变密**：装饰间距从 200 屏幕像素缩到 105，但 emoji 尺寸按 clamp 不变，
   画面看起来像被「压缩」，同屏的信息量翻几倍，眼睛累。
2. **按视野面积画的东西全部翻倍**：背景格子数按 `1/scale²` 涨，食物球、装饰的绘制量跟着涨；
   低端机在这里最容易掉帧。

现在把 `CAMERA_MIN` 收到 **0.75**：可见面积 1.8 倍，绘制量涨不到一倍；
「我变大了」改由球本身承担（屏幕上 40 → 57px）。同时把场地也从 `450+1.7r` 收到 `360+0.6r`：
相机不退那么远了，场地就不该继续疯长，否则满级时食物铺到屏幕外 430px，一屏只看得见两三个。

实测（Edge + CDP 计数）：
每帧 canvas 调用约 12 次（`fillText` ≈ 5、`drawImage` ≈ 5、`arc` ≈ 1），
正常 60fps，CPU 6 倍节流 58fps，10 倍节流 48fps —— 吃到满级也不会掉到卡顿区间。

#### 四档难度（只改选项数，用户新提）

| 档位 | 待选单词 | 说明 |
| --- | --- | --- |
| 简单 | **4** | 先熟悉手感，场上只有 3 个干扰项 |
| 普通 | **6** | 默认档，干扰适中 |
| 复杂 | **8** | 形近词更多 |
| 困难 | **10** | 满场干扰，接近原来的固定难度 |

- 定义在 `engine.ts` 的 `DIFFICULTIES`，`createOrbGame({ difficulty })` 决定本局；
  一局内的 `state.options` 存住这个数，补位时才知道该补到几个。
- **只改选项数**：速度（恒 300px/s）、血条、时长、吃对/吃错倍率一律不动 ——
  否则玩家会以为「简单档连移动都变慢了」。
- 场地跟着收：`fieldRadius` 乘 `√(选项/10)`，4 个球铺在 10 个球的场地里会显得空旷、
  要走很久才碰到一个。
- 入口两处：选词库页顶部（开打前选）、准备弹层（开打前也能换，换了立刻重建这一局）；
  选择存在 `knowflow.play.difficulty`，下次进来还是这一档。
- 未知档位由 `difficultyOf()` 回落「普通」，以后加档位不用改存档兼容逻辑。

#### 出词模式：顺序 / 随机（用户反馈「十几个词轮回」）

**问题**：球球和跑酷原来都是「洗牌后只取 30 个词，本局在这 30 个里循环」。
玩两三局就把 30 个词背熟了，剩下的 4400 个词根本没机会出现。

**改法**（`src/games/words.ts`，两个游戏共用）：

| 模式 | 行为 | 游标 |
| --- | --- | --- |
| **顺序**（默认） | 按词库原有顺序逐词出，整个词库刷完一轮前不重复；下一局从上次的位置继续 | `knowflow.play.cursor` 按词库存 `{ packId: index }`，每答对一题推进一格并落盘 |
| **随机** | 整库洗牌，一局内不重复，每局顺序不同 | 不记游标 |

- 词池 = **整个词库**（不再是 30 个）；取词顺序是 `buildWordOrder(mode, total, startIndex, shuffle)`。
- 干扰项不在整库上挑：`buildDistractorPool()` 先随机抽 240 个当候选池（形近词评分只在这上面排序，
  整库 4000+ 条时每挑一次都排一遍太浪费）；顺序模式还会把「接下来 20 个词」塞进去，
  让干扰项和当前关卡水平接近。
- 游标越界自动取模（写坏了也不会崩），选词库页有「已刷 N / 总数」和「从头开始」。
- 选词库页可随时切换模式；切换会重建这一局。
- `cleanWords()` 过滤缺词/缺释义/占位释义 —— 见下面「am 找不到解释」那条。

#### 修数据：`am` 显示「找不到解释」

初中词库（junior）的源表里有 **17 条**占位释义，都是 `找不到解释`（am / August / Internet /
Thanksgiving / p.m. / X-ray …），出题时直接显示成题干，等于废题。

- 已按词条补齐这 17 个释义（`frontend/data/words/junior.psv`），`npm run build:packs` 重新生成；
- 同时在 `cleanWords()` 里兜一层：命中 `找不到解释 | 暂无释义 | 未找到释义 | 无` 的词一律不进游戏，
  以后换词库再混进占位也不会污染题目。

#### 「吃越多越慢」到底是怎么修干净的

三层，缺一层都还会被反馈：

1. **公式层**：屏幕速度 = 世界速度 × cameraScale(r) = 定值。`moveSpeed(r) = speedBase / cameraScale(r)`，
   r 从 40 长到 76 时世界速度从 300 涨到 570，屏幕上永远是 300 px/s。
2. **帧率层**：只要帧率掉到 20fps 以下，`dt` 被 50ms 夹住就意味着「每帧只算 50ms」，
   一秒钟只推进 15×50=750ms 的量 —— 速度凭空少四分之一。
   现在页面用 `acc += 真实间隔` 再按 1/120 秒固定步长补齐（上限补 250ms），引擎 dt 放宽到 100ms：
   **掉帧只会更卡，不会更慢**。单测直接对比「60fps 与 20fps 各跑 1 秒」的屏幕位移必须相等。
3. **绘制层**（保险，不是主因）：视野变大时背景格子按 `1/scale²` 涨，超过 26 格就隔格抽样；
   食物球「球 + 英文」预渲染成精灵，每帧只 `drawImage`，文字绘制从每球 1~3 次 `fillText` 归零；
   玩家球的径向渐变按「半径+中心」缓存，不再每帧新建；排版结果按「词+宽度+字号」缓存。
   实测每帧 canvas 调用约 12 次，10 倍 CPU 节流仍有 48fps。

> 校正：这一轮实测下来，页面本来就不是帧率瓶颈（正常 60fps、10 倍节流 48fps），
> 所以「越吃越慢」的主因是**视野越退越远带来的速度感变化**（同屏参照物变小变密，像慢镜头），
> 而不是掉帧。固定步长与绘制优化仍然保留 —— 它们把「低端机上万一掉帧就会真的变慢」这条路堵死了，
> 属于兜底而不是主修复。

实测（`test:orb`）：r=40 与 r=76 各跑 1 秒，屏幕位移都是 269.2px；60fps 与 20fps 也都是同一数值。

### 3.2a 球上的字怎么排（用户反馈过两轮）

| 问题 | 原因 | 现在 |
| --- | --- | --- |
| 英文单词被截成「abando…」 | 旧规则只在 **≥11 字母**时折行；9~10 字母既放不进一行也不折行，而 cet4 有 571 个、cet6 有 835 个落在这个区间 | 改成「放不下一行就折」，最多三行；只有三行都放不下（比球还窄）才截断 |
| 中文释义只剩两三个字 | `targetLabel` 按**逗号**切 + 上限 8 字 → 「准时的，守时的」只剩「准时的」 | 按**分号**切第一个义项、保留逗号，上限 15 字；球上最多三行 |
| 球内还是放不下全部意思 | 球就那么大，15 字已是极限（再挤就得缩字号，会重演「看不清」） | 屏幕上方提示条改用 `fullLabel`：**保留全部义项**、上限 40 字、可换行；球内继续放短义 |
| 显示到「adv.…」 | 词性标记夹在释义中间（`n.锁v.锁,锁上`），只剥开头那个不够 | 词性全部转成义项分隔符再取第一个义项，不把两个义项黏成一句 |

回归测试落在 `test:orb`（targetLabel 取值）与 `test:orb:render`（假 canvas 记录 fillText，
断言画出来的字里没有省略号）。

两个口径的分工（`fullLabel` vs `targetLabel`）：

| 位置 | 用哪个 | 内容 | 字号 / 行数 |
| --- | --- | --- | --- |
| 玩家球内 | `targetLabel` | 第一个义项 | 最多 3 行，随球大小缩放 |
| 屏幕上方提示条 | `fullLabel` | **全部义项**，词性转成「；」分隔 | 12px，最多 2~3 行（横条宽度够） |

提示条与「升级 / 回血」横幅放在同一个 `flex-col` 容器里，不再各自绝对定位 ——
否则长释义换行后两者会叠在一起。

### 3.2b 另外三个玩法

| 玩法 | 机制 | 为什么这样做 |
| --- | --- | --- |
| 成语填空 | 每个成语挖掉一个字，4 个候选字里选回来；答错扣命、断连击，60 秒 | 原占位是「成语接龙」，但内置 172 条成语里只有 **22 条（13%）的末字能接上别的首字**，严格接龙两步就断，几乎每局都在「链断了」。换成同数据撑得住的填空，考的还是成语熟悉度 |
| 中英配对 | 8 对（英文 / 中文）铺成 4×4，翻两张，配上了消除；90 秒，全部配完按剩余时间给奖励 | 纯记忆翻牌，不依赖读题速度；没配出来的词结算时批量入队 |
| 单词跑酷 | 三条跑道，每波三扇门各写一个英文词，上方只给中文；换道穿过对的那扇，撞错扣命 | 把「认词」压进反应时间；跑动感比静态选择题更能撑住连续 60 秒 |

两个玩法的引擎同样是纯函数（`src/games/idiom/engine.ts`、`src/games/pair/engine.ts`）：
种子存在 state 里可复现，「翻错 0.75 秒后盖回去」也放在引擎的 `tick` 里，
页面不用自己维护定时器，组件卸载时不会留下幽灵 setTimeout。

成语填空的干扰字只从**成语字池**里取，且优先取「同位置出现过的字」——
从整个汉字库乱抽的话，一眼就能排除，等于白送分。

跑酷的坑位是按「当前目标词 + 两个形近干扰词」铺的，干扰词复用球球那套
`spellSimilarity`（首字母 / 长度 / 公共前缀），所以三扇门看起来都不像白送。

#### 跑酷的几个实现细节

| 项 | 做法 | 原因 |
| --- | --- | --- |
| 判定时机 | 门进入 x 的命中窗口时，只判定玩家所在那条道 | 三条道各判一次会出现「一次穿两门」 |
| 目标推进 | `waveAdvanced` 标记，一波只换一次目标 | 早先按「门都飞出屏幕」判断，三扇门 x 不完全同步时会连续多换几次，中文提示跟着闪 |
| 换道 | 键盘 ↑↓/WS、点哪条道就去哪条、右下角箭头 | 三种输入都覆盖，手机上单手也能玩 |
| 提速 | `baseSpeed` 随分数线性上涨，设上限 | 不设上限后段门速会超过人的反应极限 |

### 3.2c 血条与回血

四个带血条的玩法（闯关 / 球球 / 成语填空 / 跑酷）共用同一条规则，
集中在 `src/games/lives.ts` 的 `LIFE_RULE`：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 初始血量 | 3 | 和原来一致，不提高难度 |
| 血量上限 | 5 | 上限必须高于初始，否则回血机制没意义 |
| 回血条件 | 连对 3 个回 1 格 | 用各玩法已有的 combo，答错清零后重新数 |

- 引擎侧只在「答对」分支加一行 `state.lives = healForStreak(...)`，不影响扣血与结束判定
- 回满即停：`Math.min(state.maxLives, lives + 1)`，不会溢出
- `maxLives` 由 `maxLivesOf()` 决定（至少 5），测试里显式传 `lives: 99` 时按传入值，便于放宽跑长局
- 反馈：球球用画布上方的横幅（`连对 3 个 · 血量 +1`），其余三个用 toast。没有提示玩家根本注意不到血条涨了

> 血条按 `maxLives` 渲染，所以初始 3 格满 + 2 格空，玩家一眼能看到「还有空间可回」。

### 3.2d 不限时（练习）模式

四个玩法都有「限时 / 练习 · 不限时」开关，默认限时：

| 项 | 做法 |
| --- | --- |
| 引擎侧 | `createXxxGame({ untimed: true })` 直接把 `duration` 设成 `Infinity`，其余逻辑一行不改 |
| HUD | 倒计时位置显示「练习」，不显示剩余秒数 |
| 结算 | 不限时也会因命耗尽结束；正确率、错词入队照常 |
| 偏好 | 记在 `knowflow.play.untimed`，四个玩法共用同一个开关状态 |
| 切换时机 | 只在准备页可切，开局后不中途改规则（改了会让同一局前后不一致） |

### 3.2e 待开发玩法（页面占位）

四个街机类玩法规则已定稿，先在卡片列表里灰着展示，让人看到方向：

| 玩法 | 规则要点 | 成本 |
| --- | --- | --- |
| 单词贪吃蛇 | 蛇头挂中文，果实写英文；吃对 +1 节并提速，吃错截尾 3 节 + 掉血；穿墙不死，撞自己结束 | 1.5 天 |
| 单词弹幕 | 敌机带英文，只打写着正确词的那架；错打扣血 | 1.5 天 |
| 单词打砖块 | 砖上写中文，球撞到时弹二选一，选对才消 | 1.5 天 |
| 单词迷宫 | 岔路口只有一条门的词对，走错退回 3 格 | 1 天 |

占位做法：`GameCard.path` 留空即为待开发 —— 卡片降透明度、标题旁挂 `Lock 待开发` 徽标、
不渲染「开始」按钮（所以点了不会跳转），成绩位置显示「规则已定稿，等排期」。
上线某个玩法只要补 `path` 与页面，这里不用再改。

> 街机型比出题型更好玩，但每分钟学到的更少：它们的价值是让人愿意多待十分钟，
> 学习效果仍然靠「吃错即入队」那条线兜着。真正补复习队列源头的是「词义速判」，不在这一批。

### 3.3 环境层级（视野升级）

不是把世界缩小，而是**相机拉远 + 背景切换**，世界坐标不变：

| 阈值（吃对个数） | 层级 | 背景 | 装饰 |
| --- | --- | --- | --- |
| 0 | 村庄 | 浅绿 | 🏡 🌳 🌾 🐄 |
| 6 | 城镇 | 灰绿 | 🏘️ 🏢 🚗 🌲 |
| 14 | 城市 | 蓝灰 | 🏙️ 🌉 🚦 🏬 |
| 24 | 省 | 浅蓝 | 🗺️ ⛰️ 🌊 🛤️ |
| 38 | 国家 | 靛蓝 | 🌏 🏔️ ☁️ 🛰️ |
| 56 | 地球 | 深空 | 🌍 ✨ 🌑 🛸 |
| 80 | 太阳系 | 近黑 | ☀️ 🪐 ⭐ 🌌 |

> 阈值从「半径」改成「吃对个数」：半径封顶 76 之后，用半径做阈值会让玩家永远停在村庄。
> 层级的本意是进度感，用吃对数更准。当前层级名常驻在 HUD 左上角（时间下方）。

切层级时背景 0.6 秒插值过渡，顶部弹「已进入 城市」提示 1.6 秒。

### 3.4 干扰项：形近词

干扰项不是随机抽，而是从本局词池里按**形近度**打分排序后取前一半随机：

```
首字母相同 +3 · 长度差越小越高（最多 +3）· 公共前缀每个字母 +1（封顶 +3）
```

随机抽词时，玩家看单词长度就能猜；形近词（adapt / adopt）逼他真去读。

### 3.5 操作

| 设备 | 操作 |
| --- | --- |
| 桌面 | 鼠标位置即方向（离中心越远越快，按住满速）；也可 WASD / 方向键 |
| 手机 | 按下处为圆心的**相对拖动**摇杆，死区 8px、行程 48px；舞台 `touch-action: none` 防页面滚动 |

用 Pointer Events 一套代码覆盖鼠标 / 触屏 / 触控笔，只有「第一根手指」生效。
摇杆一定做相对拖动 —— 绝对定位要求手指正好按在摇杆上，手机上会漏掉一半手势。

### 3.6 渲染

Canvas 2D，`devicePixelRatio` 缩放（上限 2 倍）。

两个刻意的取舍：

1. **全部在屏幕坐标里画，不 `ctx.scale`**。相机缩到 0.5 时，如果连文字一起缩，
   单词会小到不可读。改为：圆的半径乘 scale，字号按屏幕像素给。
   食物球视觉半径设 13px 下限（略大于真实碰撞半径，手感更宽容）。
2. **环境装饰用「世界网格 + 哈希」生成**，不存数组。走到哪都有装饰，又不用维护会越铺越大的地图。

其它：字号按球半径自适应（9~18px）→ 放不下就截断加省略号；中文短义按字折行、最多两行；
粒子上限 12 个；不做阴影和发光（离屏绘制开销）。

### 3.7 引擎是纯函数

```ts
createOrbGame({ words, seed }) → OrbState
startOrb(state) → OrbState          // ready → playing
stepOrb(state, dt, dir) → OrbState  // 输入 + 时间步 → 新状态
```

- 不碰 DOM、不读系统时间、不用 `Math.random`：随机数走 state 里的 LCG 种子，
  所以单测可以复现每一局，线上也不会因为掉帧出现不可解释的状态
- `dt` 夹在 50ms：切标签回来时 dt 可能是好几秒，不夹住球会瞬移穿过所有食物
- 渲染层只读 state；一次「吃」通过 `state.lastHit.seq` 通知页面撒粒子

### 3.8 答错入队

- 结算时**批量**入队（`addWordToReview(packId, word, true)`），不在游戏过程中逐次写 IndexedDB
- 记录的是**没认出来的目标词**（你看到中文却没找到对应英文），不是那个被误吃的干扰词
- 答对不动 SRS，只 `saveGameResult` 记成绩；结算页显示「已加入 N 个词到复习队列」
