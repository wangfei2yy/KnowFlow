## 二、进度记忆

三个独立的 localStorage 域，读写全部 try/catch 静默（存不下也不能卡住这一局）。

### 2.1 闯关会话 `knowflow.quest.session`

```ts
{ [packId]: { packId, session: QuestSession, savedAt: ISO 字符串 } }
```

| 时机 | 行为 |
| --- | --- |
| 每次作答后、切到下一题后 | 写入（整份会话，只存 index 没意义，题目是每局重抽的） |
| `session.finished` | 清掉**该词库**的存档 |
| 读取 | 过滤掉「已结束 / 题目为空 / 超过 7 天」的脏数据并写回 |

按词库分开存，是为了「有 cet4 存档时切到 cet6」不会把 cet4 的半局冲掉。

`resumeSession()` 处理一个边界：用户是在「已作答、还没切下一题」的瞬间退出的，
直接恢复会卡在一道不能操作的题上，所以恢复时自动推进一格；推进后已到末尾则视为这局结束、不再恢复。

### 2.2 复习位置 `knowflow.study.position`

```ts
{ fingerprint: string, index: number }
```

`fingerprint` 是当前复习队列卡片 id 串起来的 djb2 哈希（带分隔符，避免 `["ab","c"]` 与 `["a","bc"]` 撞车）。

- 队列没变 → 停在上次那张
- 队列变了（标记掌握后队列缩短）→ 丢弃旧位置，回到第 1 张，不越界
- 只在「队列模式 + 复习视图」下记录；列表视图、临时筛选、`?mode=all` 都不写，
  免得把正常复习的位置覆盖成浏览时的位置

### 2.3 游戏成绩 `knowflow.game.progress`

```ts
{ [gameId]: { [packId]: { bestScore, plays, lastPlayedAt } } }
```

球球走这个新键，闯关沿用旧的 `knowflow.quest.progress`，两者不混。

## 三、单词球球

### 3.1 玩法

```
玩家球：写着【当前目标词的中文短义】（≤8 字）
食物球：写着【英文单词】，场上 10 个，其中恰好 1 个是正确答案
吃对  → 球 ×1.08，得分 +10（连击 +2/次，封顶 +10），换下一个目标词
吃错  → 球 ×0.88，扣 1 条命，屏幕抖动，目标词不变（还得继续找它）
结束  → 3 条命耗尽，或 60 秒倒计时归零
```

为什么玩家球放中文、食物球放英文：英文 1~3 个词放得下，中文释义动辄十几个字塞不进小圆；
反过来会两个都看不清。

### 3.2 数值表

| 项 | 值 | 说明 |
| --- | --- | --- |
| 初始半径 | 40 | 世界单位 |
| 吃对增长 | ×1.08（复利） | 约 9 次翻倍 |
| 吃错缩小 | ×0.88 | 两次吃错约退回起点 |
| 半径下限 | 24 | 防止缩没 |
| 移动速度 | `250 / (1 + r/160)` | 越大越慢，避免大球无脑碾压 |
| 初始命 / 时限 | 3 / 60 秒 | |
| 场上食物 | 10 个 | 吃掉后立刻补位（之前 14 个太密，选项一多反而难找） |
| 连击 | 连续答对 +2 分/次，最高 +10 | 答错清零 |
| 相机缩放 | `clamp(40/r, 0.35, 1)` | r=40 → 1.0；r≥115 → 0.35 |
| 可吃区域半径 | `560 + r × 1.7` | 球越大，可找的范围越大 |

数值集中在 `src/games/orb/engine.ts` 的 `ORB` 常量里，调手感只改这里。

### 3.2b 另外三个玩法

| 玩法 | 机制 | 为什么这样做 |
| --- | --- | --- |
| 成语填空 | 每个成语挖掉一个字，4 个候选字里选回来；答错扣命、断连击，60 秒 | 原占位是「成语接龙」，但内置 172 条成语里只有 **22 条（13%）的末字能接上别的首字**，严格接龙两步就断，几乎每局都在「链断了」。换成同数据撑得住的填空，考的还是成语熟悉度 |
| 中英配对 | 8 对（英文 / 中文）铺成 4×4，翻两张，配上了消除；90 秒，全部配完按剩余时间给奖励 | 纯记忆翻牌，不依赖读题速度；没配出来的词结算时批量入队 |
| 单词跑酷 | 三条跑道，每波三扇门各写一个英文词，上方只给中文；换道穿过对的那扇，撞错扣命 | 把「认词」压进反应时间；跑动感比静态选择题更能撑住连续 60 秒 |

两个玩法的引擎同样是纯函数（`src/games/idiom/engine.ts`、`src/games/pair/engine.ts`）：
种子存在 state 里可复现，「翻错 0.75 秒后盖回去」也放在引擎的 `tick` 里，
页面不用自己维护定时器，组件卸载时不会留下幽灵 setTimeout。

成语填空的干扰字只从**成语字池**里取，且优先取「同位置出现过的字」——
从整个汉字库乱抽的话，一眼就能排除，等于白送分。

跑酷的坑位是按「当前目标词 + 两个形近干扰词」铺的，干扰词复用球球那套
`spellSimilarity`（首字母 / 长度 / 公共前缀），所以三扇门看起来都不像白送。

#### 跑酷的几个实现细节

| 项 | 做法 | 原因 |
| --- | --- | --- |
| 判定时机 | 门进入 x 的命中窗口时，只判定玩家所在那条道 | 三条道各判一次会出现「一次穿两门」 |
| 目标推进 | `waveAdvanced` 标记，一波只换一次目标 | 早先按「门都飞出屏幕」判断，三扇门 x 不完全同步时会连续多换几次，中文提示跟着闪 |
| 换道 | 键盘 ↑↓/WS、点哪条道就去哪条、右下角箭头 | 三种输入都覆盖，手机上单手也能玩 |
| 提速 | `baseSpeed` 随分数线性上涨，设上限 | 不设上限后段门速会超过人的反应极限 |

### 3.2c 血条与回血

四个带血条的玩法（闯关 / 球球 / 成语填空 / 跑酷）共用同一条规则，
集中在 `src/games/lives.ts` 的 `LIFE_RULE`：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 初始血量 | 3 | 和原来一致，不提高难度 |
| 血量上限 | 5 | 上限必须高于初始，否则回血机制没意义 |
| 回血条件 | 连对 3 个回 1 格 | 用各玩法已有的 combo，答错清零后重新数 |

- 引擎侧只在「答对」分支加一行 `state.lives = healForStreak(...)`，不影响扣血与结束判定
- 回满即停：`Math.min(state.maxLives, lives + 1)`，不会溢出
- `maxLives` 由 `maxLivesOf()` 决定（至少 5），测试里显式传 `lives: 99` 时按传入值，便于放宽跑长局
- 反馈：球球用画布上方的横幅（`连对 3 个 · 血量 +1`），其余三个用 toast。没有提示玩家根本注意不到血条涨了

> 血条按 `maxLives` 渲染，所以初始 3 格满 + 2 格空，玩家一眼能看到「还有空间可回」。

### 3.2d 不限时（练习）模式

四个玩法都有「限时 / 练习 · 不限时」开关，默认限时：

| 项 | 做法 |
| --- | --- |
| 引擎侧 | `createXxxGame({ untimed: true })` 直接把 `duration` 设成 `Infinity`，其余逻辑一行不改 |
| HUD | 倒计时位置显示「练习」，不显示剩余秒数 |
| 结算 | 不限时也会因命耗尽结束；正确率、错词入队照常 |
| 偏好 | 记在 `knowflow.play.untimed`，四个玩法共用同一个开关状态 |
| 切换时机 | 只在准备页可切，开局后不中途改规则（改了会让同一局前后不一致） |

### 3.3 环境层级（视野升级）

不是把世界缩小，而是**相机拉远 + 背景切换**，世界坐标不变：

| 阈值（半径） | 层级 | 背景 | 装饰 |
| --- | --- | --- | --- |
| 40 | 村庄 | 浅绿 | 🏡 🌳 🌾 🐄 |
| 80 | 城镇 | 灰绿 | 🏘️ 🏢 🚗 🌲 |
| 140 | 城市 | 蓝灰 | 🏙️ 🌉 🚦 🏬 |
| 220 | 省 | 浅蓝 | 🗺️ ⛰️ 🌊 🛤️ |
| 320 | 国家 | 靛蓝 | 🌏 🏔️ ☁️ 🛰️ |
| 450 | 地球 | 深空 | 🌍 ✨ 🌑 🛸 |
| 600 | 太阳系 | 近黑 | ☀️ 🪐 ⭐ 🌌 |

切层级时背景 0.6 秒插值过渡，顶部弹「已进入 城市」提示 1.6 秒。

### 3.4 干扰项：形近词

干扰项不是随机抽，而是从本局词池里按**形近度**打分排序后取前一半随机：

```
首字母相同 +3 · 长度差越小越高（最多 +3）· 公共前缀每个字母 +1（封顶 +3）
```

随机抽词时，玩家看单词长度就能猜；形近词（adapt / adopt）逼他真去读。

### 3.5 操作

| 设备 | 操作 |
| --- | --- |
| 桌面 | 鼠标位置即方向（离中心越远越快，按住满速）；也可 WASD / 方向键 |
| 手机 | 按下处为圆心的**相对拖动**摇杆，死区 8px、行程 48px；舞台 `touch-action: none` 防页面滚动 |

用 Pointer Events 一套代码覆盖鼠标 / 触屏 / 触控笔，只有「第一根手指」生效。
摇杆一定做相对拖动 —— 绝对定位要求手指正好按在摇杆上，手机上会漏掉一半手势。

### 3.6 渲染

Canvas 2D，`devicePixelRatio` 缩放（上限 2 倍）。

两个刻意的取舍：

1. **全部在屏幕坐标里画，不 `ctx.scale`**。相机缩到 0.35 时，如果连文字一起缩，
   单词会小到不可读。改为：圆的半径乘 scale，字号按屏幕像素给。
   食物球视觉半径设 13px 下限（略大于真实碰撞半径，手感更宽容）。
2. **环境装饰用「世界网格 + 哈希」生成**，不存数组。走到哪都有装饰，又不用维护会越铺越大的地图。

其它：字号按球半径自适应（9~18px）→ 放不下就截断加省略号；中文短义按字折行、最多两行；
粒子上限 12 个；不做阴影和发光（离屏绘制开销）。

### 3.7 引擎是纯函数

```ts
createOrbGame({ words, seed }) → OrbState
startOrb(state) → OrbState          // ready → playing
stepOrb(state, dt, dir) → OrbState  // 输入 + 时间步 → 新状态
```

- 不碰 DOM、不读系统时间、不用 `Math.random`：随机数走 state 里的 LCG 种子，
  所以单测可以复现每一局，线上也不会因为掉帧出现不可解释的状态
- `dt` 夹在 50ms：切标签回来时 dt 可能是好几秒，不夹住球会瞬移穿过所有食物
- 渲染层只读 state；一次「吃」通过 `state.lastHit.seq` 通知页面撒粒子

### 3.8 答错入队

- 结算时**批量**入队（`addWordToReview(packId, word, true)`），不在游戏过程中逐次写 IndexedDB
- 记录的是**没认出来的目标词**（你看到中文却没找到对应英文），不是那个被误吃的干扰词
- 答对不动 SRS，只 `saveGameResult` 记成绩；结算页显示「已加入 N 个词到复习队列」
