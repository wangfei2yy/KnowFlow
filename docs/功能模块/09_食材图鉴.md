# 模块 09 · 食材图鉴（营养与功效）

> 目标：把「食材本身」补上 —— 营养、功效、挑选保存、宜忌，以及它在哪些菜里出现。
> 入口放在饮食模块第 4 个 Tab，**学习中心不加 Tab**；记忆动作复用现有 SRS，
> 图鉴里点「加入复习」，卡片直接进学习中心的复习队列。

---

## 一、为什么放饮食，而不是学习中心

| 理由 | 具体 |
| --- | --- |
| Tab 已经满了 | 学习中心现有 6 个（概览/复习/语法/成语/单词/趣味学习），手机端是靠隐藏图标、压到 13px 字号才一屏放下的；6 个已是上限 |
| 入口会重复 | 侧边栏已有一级入口「饮食」。再加「学习-饮食」，用户不知道从哪进 |
| 心智不对 | 「做菜」靠动手，不靠复习；把它塞进复习队列是负担 |

结论：**内容归饮食，记忆动作归学习中心**。图鉴负责看，SRS 负责记，一条线不重复。

## 二、数据

### 2.1 来源与口径

| 项 | 内容 |
| --- | --- |
| 源表 | `frontend/data/food/ingredients.psv`（竖线分隔，入库，可直接改行加条目） |
| 编译 | `npm run build:food` → `public/packs/ingredients.json` |
| 数值口径 | **每 100g 可食部**，常见品种参考值；没测过的字段留空，不填 0 |
| 规模 | 154 条（蔬菜 61 / 水果 36 / 肉类 11 / 水产 11 / 谷物 9 / 菌菇 8 / 豆类 8 / 坚果 4 / 蛋 3 / 奶 3） |
| 季节 | 不入表，编译时从 `seasons.json` 反查继承（名称或别名对上即算），90 条带上季节 |

调味料（盐、油、酱油、醋、料酒、糖、淀粉、味精、鸡精、番茄酱、甜面酱）**不进图鉴**：
没有学习价值，营养表也毫无意义。

> 为什么用 `|` 而不是逗号：释义里全是中文逗号，用 CSV 必然串列。

### 2.2 条目结构

```ts
interface IngredientEntry {
  name: string;            // 名称，同时是路由/去重用的 id
  alias?: string[];        // 别名，搜索与食谱反查都会用到
  emoji: string;           // 卡片图标（实拍图后续替换，img 字段先不加）
  category: IngredientCategory;
  seasons: string[];       // 空数组 = 四季常见，不标「当季」
  nutrition: { kcal: number; protein?; carb?; fat?; fiber?; vc?; potassium?; calcium?; iron?; carotene? };
  benefit: string;         // 功效，只写营养学表述
  storage: string;         // 挑选与保存
  caution?: string;        // 宜忌，写「什么人少吃」而非「治什么病」
}
```

### 2.3 合规红线（唯一口径）

只能写**营养素 + 已知生理功能**，不能写疾病治疗/预防。

| ✅ 可以写 | ❌ 不能写 |
| --- | --- |
| 富含维生素 C，参与胶原蛋白合成，有助于维持正常免疫功能 | 多吃能防感冒、抗病毒 |
| 钾含量较高，有助于维持正常血压 | 降血压、治高血压 |
| 膳食纤维丰富，有助于维持正常肠道功能 | 治便秘、排毒、清肠 |

`caution` 写提示不写结论：「草酸偏高，建议焯水后食用」而不是「肾结石不能吃」。
`npm run test:food` 里有 11 个禁用词的黑名单，命中即挂。

## 三、页面

### 3.1 路由

```
/kitchen/ingredient   食材图鉴（KitchenTabs 第 4 项「食材」）
```

### 3.2 列表

- 搜索：名称、别名、功效、分类名都能搜（搜「补铁」也能出结果）
- 分类 chips：全部 / 蔬菜 / 菌菇 / 水果 / 豆类 / 谷物 / 肉类 / 水产 / 蛋类 / 奶类 / 坚果
- 「只看当季」开关：按当前月份判断（3-5 春、6-8 夏、9-11 秋、12-2 冬）
- 排序：当季优先 → 分类顺序 → 名称
- 卡片：emoji + 名称 + `kcal · 分类` + 一个亮点标签（维 C 高 / 胡萝卜素高 / 纤维多 / 钙高 / 铁高 / 蛋白高 / 低热量）

### 3.3 详情（弹层）

营养表（只显示有值的字段）→ 功效 → 挑选与保存 → 宜忌（琥珀色提示条）→
「用得上它的菜」（最多 5 条，点开在食谱页打开）→ 底部 `加入复习`。

页脚常驻一句：数据为常见品种参考值，不同产地会有差异，不作为医疗或膳食处方依据。

## 四、学习闭环

```
图鉴详情 → 加入复习 → 生成卡片 → SRS 排期 → 学习中心「今日待复习」→ 复习页翻卡
```

- 桥接复用 `services/quest/wordCards.ts#addWordToReview("food", word, false)`
- `wrong = false`：主动加入按「新卡」进队，不当作答错（与成语页一致）
- 卡片挂在自动创建的《食材图鉴（饮食）》资料下，分类是「饮食」
- 卡片答案：`每 100g 约 20 kcal；富含番茄红素与维生素 C…`（≤70 字，超长截断功效）
- 已在队列里的食材，按钮显示「已加入复习」，不会重复插入

**不调 AI**：卡片文案由营养数据本地拼装。加入复习是零散高频动作，不该等联网。

## 五、双向反查

| 方向 | 实现 |
| --- | --- |
| 食材 → 菜 | 详情里 `recipesUsing()` 扫 `recipes.json` 的材料，命中名称或别名即列出（最多 5 条） |
| 菜 → 食材 | 食谱详情里，材料标签**有收录才可点**（`findIngredient()` 判断），点击跳 `/kitchen/ingredient?focus=番茄` 并直接展开 |

没收录的材料保持纯文本灰色，不报错、不弹空页。

## 六、饮食计划里的食材构成

购物清单下方新增一块「本周食材构成」：把清单里的材料按图鉴分类归类计数
（蔬菜 N 种 / 肉类 M 种…），并标注 `共 X 种材料，其中 Y 种已收录图鉴`。

**只数种数，不折算热量** —— 原始菜谱只写「适量」，没有份量。硬算热量只会得出一个假数字，
不如老实说清楚。

## 九、已知取舍

| 项 | 取舍 | 原因 |
| --- | --- | --- |
| 营养数值 | 参考值，不标数据来源版本 | 常见品种差异大，标版本反而给出「精确」的错觉；统一免责更诚实 |
| 食材图片 | 先用 emoji | 无实拍素材；换图只改渲染层，不动数据结构 |
| 计划页营养合计 | 只统计种数 | 菜谱没有份量，算热量是编数字 |
| 食材收录范围 | 154 种，以时令表 + 常见肉蛋豆谷为准 | 覆盖日常够用；缺的走「未收录」提示，不硬凑 |
