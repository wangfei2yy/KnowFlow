# 模块 04 · 陪伴机器人「小知」

> 有温度的 AI 学习伙伴：聊天答疑、Function Calling 一步直达、好感度养成。
> 返回主文档：[项目说明文档](../项目说明文档.md)

---

## 一、能力总览

| 能力 | 是否需要 AI | 说明 |
| --- | --- | --- |
| 学习鼓励 | 否 | 新增资料、完成任务、复习卡片时气泡正向反馈 |
| 软件答疑 | 否 | 内置 FAQ：软件作用、怎么新增资料、如何提取任务等 |
| 资料库问答 | 否 | 问「资料库有哪些资料」，列出标题、分类、标签与摘要 |
| 学习统计问答 | **否（纯本地）** | 问「学习中心有多少学习卡片」等统计问题，直接读本地数据回答，不消耗 AI 额度 |
| AI 智能对话 | 是 | 接入真实模型后自由聊天；AI 失败自动降级本地规则 |
| **Function Calling 工具调用** | 是 | 一句话触发卡片 / 摘要 / 任务等操作，直接落地 |

## 二、Function Calling（核心玩法）

### 2.1 工作流程

```
用户消息 ──► AI 意图识别（返回结构化 JSON）
              │  {"tool": "flashcards", "target": "SQL 入门"}
              ▼
         解析 tool + target（括号配对解析，失败走正则兜底）
              ▼
         执行对应工具 ──► 结果直接写入并反馈
```

- **意图识别交给模型**：小知的系统提示词要求 AI 从消息中判断用户想用哪个模块，返回 `{tool, target}` JSON——比正则关键词匹配更准、更能理解口语化表达（如「把 SQL 做成卡片」）
- **降级兜底**：AI 未返回合法 JSON 时，回退到本地正则关键词匹配
- **纯本地能力零成本**：`stats` 类查询在进入 AI 之前就由本地数据直接回答，不耗额度、不受 Key 限制

### 2.2 支持的工具

| tool | 触发示例 | 执行结果 |
| --- | --- | --- |
| `flashcards` | 「把 SQL 做成卡片」「帮我把周会记录做成记忆卡片」 | 调 AI 生成卡片并**直接存入学习中心**，回复生成张数 |
| `summary` | 「总结一下 XX」 | 调 AI 生成摘要并保存到资料 |
| `tasks` | 「从 XX 提取任务」「帮我把待办整理出来」 | 调 AI 提取行动项并加入任务清单 |
| `stats` | 「学习中心有多少卡片」「我掌握得怎么样」 | 本地统计：卡片总数、掌握度分布、掌握率、资料数、待办数 |
| `storage` | 「我本地存了多少数据」「缓存占多少」 | 本地统计：按分区列出有数据的分类与条数（设置页同款分组） |
| `cleanup` | 「把小游戏成绩清掉」「清空所有学习记录」 | **先确认再删**：回一条清单，用户回「确认」才执行；「算了」即放弃 |
| `chat` | 其他闲聊/提问 | 走普通 AI 对话（注入资料库概览上下文） |

### 2.3 约束与体验细节

- AI 回复注入**资料库上下文**（最多 50 条资料的标题/分类/摘要），保证回答「看得到」用户的内容
- 系统提示词包含「不得推诿」指令：能做的事直接做，不回复「我这边看不到哦」这类推脱
- 工具执行失败（如资料不存在、无 AI Key）时给出具体原因和下一步建议
- 示例资料中无任务可提取时，提示友好化而非报错
- 消息列表**一旦有新消息就滚到底**：工具调用要查库，回复是异步落进来的，
  发送时那次滚动早跑完了，不盯住 `messages.length` 回复会停在视口外

## 三、好感度与形态进化

### 3.1 好感度规则

| 行为 | 好感度 |
| --- | --- |
| 新增资料 | +3 |
| 完成任务 | +5 |
| 掌握卡片 | +4 |
| 文件导入 | +3 |
| AI 操作 | +2 |
| 搜索 / 聊天 | +1 |

好感度与对话记录保存在浏览器 localStorage。

### 3.2 关系等级（7 级）

初识 → 熟悉 → 信赖 → 亲密 → 挚友 → 知己 → 灵魂伙伴

### 3.3 三种形态（随好感度自动进化）

| 形态 | 触发条件 | 视觉 |
| --- | --- | --- |
| 幼芽形态 | 好感度 < 30 | 静态小机器人 |
| 成长形态 | 好感度 ≥ 30 | 带四肢、会挥手动腿 |
| 蜕变形态 | 好感度 ≥ 60 | 透视 + 光影 + 悬浮的立体感 |

形态由好感度自动升级，无需手动切换。

## 四、交互体验

- **可拖动**：悬浮头像可按住拖到屏幕任意位置（自动限制在可视区域内，不会拖出屏幕关不掉）；拖动与点击通过 `suppressClick` 标志区分，避免拖拽结束时误触弹窗。移动端必须给悬浮球加 `touch-action: none`（`touch-none`），否则触摸拖动会被浏览器判为页面滚动并触发 `pointercancel`，表现为「每次只能拖动一点」；同理面板顶部调高条也需要
- **聊天框可调高**：面板顶部有拖拽条，上下拖动调整聊天框高度（默认 480px）
- **面板定位**：聊天面板绝对定位跟随头像，不会被挤压错位
- **头像自定义**：支持上传自己的图片（2MB 以内）作为形象，自动裁剪为圆形，可随时「恢复默认形象」
- **可开关**：默认开启，可在面板右上角或「设置」页随时关闭

## 五、语音输入（按住说话）

微信式交互：**按住麦克风 → 说话 → 松手自动发送**。转出的文字直接走 `sendMessage`，因此和打字完全同权，一样能触发 function calling（例：按住说「把 SQL 笔记做成卡片」，松手后自动生成卡片）。

### 5.1 两种识别通道

| 通道 | 触发条件 | 特点 |
| --- | --- | --- |
| 录音上传转写（whisper 协议） | 配置了语音转写服务（见 5.4，或复用主 AI Key） | 中文更准、跨浏览器一致；调用 `{baseUrl}/audio/transcriptions` |
| 浏览器原生识别（Web Speech API） | 未配 Key，且浏览器支持 `webkitSpeechRecognition` | 免费、无需 Key、边说边出字；依赖浏览器语音服务（Chrome 需联网） |

选择逻辑在 `useVoiceInput` 的 `mode` 计算属性里：小工具容器内一律 `none`（无麦克风权限、无网络），其余情况按上表降级。

> 兼容性提醒：**手机百度浏览器、微信内置浏览器等没有 Web Speech API**（`webkitSpeechRecognition` 缺失），原生识别通道不可用；这类环境必须配置 API Key 走转写通道（它们的 `getUserMedia` / `MediaRecorder` 是支持的），或改用手机 Chrome / Safari 打开。

### 5.2 交互细节

- **上滑取消**：按住后向上滑动超过 56px，提示变「松开手指，取消发送」，松手即丢弃录音
- **实时反馈**：录音条显示红点、5 根跳动的波形条、秒数，以及实时识别文字（浏览器通道）或「正在转成文字…」（上传通道）
- **时序兜底**：若在申请麦克风权限期间就松手，会用 `pendingStop` 记录松手意图，启动完成后立即按意图结束，不会出现「松手了还在录」
- **错误可见**：面板打开时鼓励气泡是隐藏的，因此语音相关提示改为面板内黄色提示条（权限被拒、没听清、说话太短、服务不支持转写）
- **上限 60 秒**：超时自动结束，避免误按长时间录音
- **不支持时也会显示按钮**：按钮常显，仅置灰并把提示改为「当前浏览器不支持语音识别…」（隐藏按钮会让用户以为功能不存在）
- **按浏览器给具体操作**：识别 UA 区分微信 / 百度 / QQ / UC / 夸克 / 小红书 / 微博 / 支付宝，提示里直接写该环境怎么做（如微信「点右上角…选择在浏览器打开」），并提供「复制链接」一键复制，方便粘贴到系统浏览器
- **首次主动提示**：第一次在第三方浏览器打开小知面板时自动弹一次提示（localStorage `knowflow.voice.hintShown` 去重），避免用户以为功能坏了
- **端内隐藏**：小工具包通过构建替身（`src/minitool/whisperRecorder.stub.ts`、`transcribe.stub.ts`）替换录音与上传模块，产物中 `getUserMedia` / `MediaRecorder` / `fetch` 出现次数均为 0，麦克风按钮也不渲染

### 5.4 独立配置语音转写（重要）

语音转写**不复用聊天模型**：设置页有独立的「语音转写（小知按住说话）」区块（服务地址 / 模型 / Key 三项，留空则跟随主 AI 配置）。原因很实际：

- Chrome 系 `webkitSpeechRecognition` 把音频上传 Google 云，**国内不可达**；百度、微信等手机浏览器连 API 对象都没有
- 聊天常用的 `api.openai.com` 国内也不可直连
- 因此语音应单独指向国内可直连的兼容服务，不影响聊天

设置页提供两个一键预设：

| 预设 | 地址 | 模型 | 特点 |
| --- | --- | --- | --- |
| 硅基流动（推荐国内） | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` | 国内直连、中文强、有免费额度；接口与 OpenAI 完全兼容 |
| OpenAI Whisper | `https://api.openai.com/v1` | `whisper-1` | 需外网 |

通道选择顺序（`useVoiceInput.mode`）：单独配了语音服务 → 直接走转写；否则浏览器有原生识别 → 用它；再否则若主 AI 配置可用于转写 → 兜底转写；都不行 → 按钮灰显并引导去设置。

> 不建议接百度智能云 ASR：需要 AK/SK 换 token、音频要转 16k PCM（浏览器录的是 webm），且 Secret Key 放前端不安全，改造量与风险都高于换一个兼容服务商。

### 5.4 Key 输入的移动端适配

手机上粘贴/回填长 Key 有两个坑，均已处理：

- **看起来「sk- 前缀被截断」**：值其实是完整的，是 iOS Safari 把长值输入框横向滚到末尾，前缀被滚出视野。处理：进入设置页、切换「显示/隐藏」、失焦时都把 `scrollLeft` 复位，并在输入框下方显示 `已保存：sk-…末四位` 的绿色摘要，可直接核对前缀是否完好
- **手机输入法改写字符**：零宽字符、换行、全角连字符（`－`）会让 Key 校验失败。保存时统一清洗（去零宽/空白字符、各种连字符归一为半角 `-`），清洗结果回写表单
- 输入框补充 `autocapitalize="off" autocorrect="off" spellcheck="false" autocomplete="new-password"`，避免 iOS 自动大写、智能标点与密码自动填充干扰

### 5.4 手机端是「点按说话」

国产手机浏览器（华为、小米等）会拦截长按手势，弹出自己的菜单（如「标记广告」），导致长按录音根本启动不了。因此按设备分两种交互：

| 设备 | 交互 |
| --- | --- |
| 电脑（鼠标） | 按住说话，松手发送；上滑取消 |
| 手机/平板（触摸） | **点一下开始录音**，再点麦克风或点「发送」结束；录音条右侧有「取消」「发送」按钮；按住超过 0.7s 再抬手也按微信方式发送 |

同时做了三层防菜单处理：按钮 `@touchstart.prevent` + `@selectmenu/@contextmenu.prevent` + CSS `-webkit-touch-callout: none`，避免系统/浏览器把长按识别成选中文字或广告操作。

### 5.3 隐私

语音文件仅在用户自备 Key 的通道下上传到**用户自己配置的服务商**，不经过本项目服务器；浏览器通道由浏览器厂商的语音服务处理。两种通道都在用户按住并松手后才发起，不做后台监听。
