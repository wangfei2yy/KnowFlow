## 一、项目概述

**知间 AI（KnowFlow）** 是一个帮助用户把零散资料转化为「可检索知识」和「实际行动」的个人资料管理工具。

它解决的问题很朴素：我们每天都在收藏、记录、囤积信息——网页片段、会议记录、学习笔记、技术文档——但真正需要的时候，往往找不到；收藏夹越来越满，价值却越来越低。

知间 AI 的答案是：**让知识不止于收藏，让信息最终成为行动。**

产品核心闭环：

```
① 收集资料 ────► 文本、笔记、文件、网页内容
② AI 理解 ────► 摘要、关键词、问答、行动项提取、学习卡片
③ 检索与复用 ──► 全文搜索、来源定位、闪卡复习
④ 转化为行动 ──► 任务清单、学习复习、导出成果
```

**一句话介绍**（可用于应用商店/发布页）：面向学生、考研党、职场学习者与所有"存了就忘"的人；支持笔记、文本、文件、网页四种导入方式，AI 自动生成摘要与学习卡片（张数可自定义或由 AI 判断），学习中心支持翻卡复习与多维筛选；陪伴机器人「小知」支持 Function Calling——打字或**按住说话**都行，说一句"把 SQL 做成卡片""看下学习中心有多少卡片"，AI 自动识别意图并调用对应模块直接完成操作。首次打开自动加载示例资料，无需注册即可完整体验。

## 二、开发初衷

### 2.1 名字的由来

「知间 AI（KnowFlow）」这个名字，承载了整个产品的理念：

| 词 | 含义 | 对应定位 |
| --- | --- | --- |
| **知** | 知识、信息、理解 | 资料管理、AI 总结、知识问答 |
| **间** | 空间与连接 | 容纳资料的个人知识空间，信息之间建立联系 |
| **Know** | 知道、理解 | 知识管理定位 |
| **Flow** | 流动、流程 | 资料经 AI 整理、检索、理解，最终转化为任务和行动 |

### 2.2 为什么做这个产品

日常生活中，几乎每个人都遇到过这些痛点：

- **学生**：课件、笔记太多，期末复习效率低；
- **职场人**：会议记录、方案、工作资料散落在各处，容易遗漏待办；
- **程序员**：技术文档、报错记录难以快速查找；
- **内容创作者**：灵感、素材、参考资料混乱，难以复用；
- **普通用户**：收藏了一大堆，真正需要时找不到。

传统收藏夹只是「存进去」，而知间 AI 让资料「活起来」——经过 AI 的理解、整理与转化，最终变成可以被执行的行动。

### 2.3 产品的差异化卖点

1. **不只是收藏夹**：资料可以进一步转化为摘要、任务和学习卡片。
2. **AI 回答有出处**：优先从用户保存的资料中回答，并展示对应原文片段，不凭空编造。
3. **Function Calling 一步直达**：对小知说一句话，AI 自动识别意图并调用对应能力（卡片/摘要/任务/统计），直接落地完成，无需翻页面。
4. **按住说话**：微信式语音输入，按住麦克风说完松手即自动发送；支持上滑取消、实时转写，转出的文字同样触发 Function Calling（说"把这份笔记做成卡片"即可）。
4. **不依赖 AI 也能用**：本地保存、全文搜索、分类、任务管理等基础功能可独立运行。
5. **体验门槛低**：首次进入自动加载 7 条示例资料（覆盖全部来源类型），打开即可体验完整流程，无需注册、无需配置。
6. **重视隐私**：默认本地存储，不要求先注册或上传个人资料。
7. **有温度的陪伴**：内置陪伴机器人「小知」，鼓励学习、解答用法，相处越久好感度越高、形态不断进化，让整理知识不再枯燥。

### 2.4 项目背景

本项目同时是 **WorkBuddy「1024 造物挑战」程序员节应用创作大赛** 的参赛作品。活动要求使用 WorkBuddy 创作并发布一件可供他人体验的应用，网页应用或小程序均可。知间 AI 以「实用工具 + AI 增强 + 本地优先」为定位，通过真实的资料处理闭环体现应用价值。

## 四、技术架构

### 4.1 技术选型

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 前端框架 | Vue 3 + TypeScript | Composition API 组件化开发 |
| 构建工具 | Vite | 快速开发与构建 |
| UI | Tailwind CSS + Lucide 图标 | 统一视觉风格 |
| 状态管理 | Pinia | 页面状态管理 |
| 路由 | Vue Router（hash 模式） | 静态托管刷新不 404 |
| 本地数据库 | IndexedDB + Dexie.js | 持久化保存资料 |
| 文件解析 | pdfjs-dist | PDF 文本提取 |
| AI 服务 | 统一 AIProvider 接口 | 可插拔，兼容 OpenAI API，支持 Function Calling 意图识别 |
| 后端（可选） | FastAPI + Python | AI 代理、密钥保护 |

### 4.2 架构设计

```
用户浏览器
  └── Vue 3 前端应用
        ├── Pinia 状态管理
        ├── 业务服务层（Service）
        │     ├── IndexedDB 本地数据（Dexie）
        │     ├── 文件解析模块（pdfjs-dist）
        │     ├── 全文检索引擎（中文 n-gram）
        │     ├── 陪伴机器人工具调用模块（companionTool）
        │     │     └── AI 意图识别 → flashcards / summary / tasks / stats / chat
        │     └── AI Provider 统一接口
        │           └── FastAPI 后端代理（可选）
        │                 └── 大模型 API
        └── JSON / Markdown 导入导出
```

### 4.3 核心设计原则

- **本地优先**：首版不强制依赖后端数据库，资料存浏览器 IndexedDB。
- **AI 可插拔**：默认 MockAIProvider，无密钥也能完整演示；接入真实模型可走 BYOK 直连或后端代理。
- **AI 驱动的工具调用**：小知的意图识别交给模型完成（返回结构化 JSON 指定 tool 与 target），正则规则仅作降级兜底；纯本地可完成的查询（如统计）不消耗 AI 额度。
- **健壮解析**：所有 AI 返回的 JSON 采用括号配对提取算法，容忍 markdown 围栏、对象包裹、尾随逗号等脏输出。
- **模块化**：业务逻辑在 Service 层，页面组件不塞业务代码。
- **安全第一**：BYOK 的 Key 只存用户本机浏览器；后端代理模式的 Key 只存服务端；AI 调用前告知发送内容；不执行资料中的 HTML/脚本。

## 六、快速开始

### 6.1 环境要求

- **Node.js** ≥ 18（推荐 22.x）
- **浏览器**：现代 Chrome / Edge / Safari（需支持 IndexedDB）
- **Python**（仅启用后端时）≥ 3.10，使用 conda 环境 `hello_agents`

详见 [开发依赖文档](开发依赖文档.md)。

### 6.2 启动前端

```bash
cd frontend
npm install
npm run dev        # 开发预览 http://localhost:5195
npm run build      # 生产构建，产出 dist/
npm run preview    # 预览生产包
```

> 首次打开会自动加载 7 条示例资料（覆盖笔记/文本/文件/网页四种来源类型，部分示例预置关联任务），可直接体验全部流程。

### 6.3 启动后端（可选，用于真实 AI）

```bash
conda activate hello_agents
cd backend
cp .env.example .env      # 编辑填入 OPENAI_API_KEY
uvicorn app.main:app --reload --port 8022   # 或直接 python run.py（默认 8022）
```

然后在「设置 → AI 配置」切换为「接入真实模型」，填入 `http://localhost:8022`。

## 七、数据模型

使用 IndexedDB（Dexie）持久化，主键 UUID，时间 ISO 8601。

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `documents` | 资料 | title, content, sourceType, categoryId, tags, summary, keywords, favorite |
| `categories` | 分类 | name, color, sortOrder |
| `tasks` | 任务 | title, status, priority, dueDate, sourceDocumentId |
| `flashcards` | 学习卡片 | question, answer, mastery, reviewCount, nextReviewAt, createdAt |
| `aiJobs` | AI 处理记录 | type, status, result, errorMessage |

数据关系：一个分类包含多份资料；一份资料关联多个任务和多张卡片；AI 记录可追溯输入资料与状态。

## 九、演示建议

用 60–90 秒演示核心价值：

1. 打开应用（自动加载示例资料），进入「项目周会记录」示例；
2. 点击「生成摘要」/「提取行动项」，展示 AI 理解与任务落地；
3. 对小知说「把 SQL 做成卡片」「帮我看下学习中心有多少学习卡片」，展示 Function Calling 一步直达；
4. 按住麦克风说「把 SQL 笔记做成卡片」，松手即自动发送并生成卡片，展示语音 + Function Calling 组合；
4. 进学习中心，切换复习/列表视图，演示分类与熟悉度筛选；
5. 资料库搜索关键词，证明资料可快速找回；
6. 展示 JSON 导出，说明知识可持续复用。
