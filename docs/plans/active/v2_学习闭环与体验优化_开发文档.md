## 1. 背景与评审结论

### 1.1 一句话结论

产品闭环已完整（导入 → AI 处理 → 卡片复习 → 任务 → 陪伴），但**「学习」主线只做了一半**：复习调度的数据写了却没人读；资料一多就缺批量与全局搜索；AI 长任务不可中断；工程层缺白屏兜底与离线能力。

优先级：**复习闭环 > 批量/全局搜索 > AI 任务可控 > 体验视觉 > 工程韧性**。

### 1.2 评审证据

| # | 问题 | 代码证据 | 用户影响 |
| --- | --- | --- | --- |
| 1 | 复习调度是「死数据」 | `Flashcard.nextReviewAt` 仅由 `services/flashcardService.ts#markMastery` 写入；全仓检索无任何读取点 | 标了「生疏/掌握」也不会再被提醒复习，间隔重复价值归零 |
| 2 | 无批量操作 | `pages/` 下 `selectedIds` / `bulkDelete` / `checkAll` 命中 0 处 | 资料超过 30 份后，改分类/删除只能逐条点 |
| 3 | 搜索只覆盖文档 | `searchDocuments` 仅 2 个调用点（HomePage、LibraryPage）；卡片、任务只有下拉筛选 | 找不到某张卡片或某条任务 |
| 4 | AI 长任务不可控 | `services/ai/` 内 `AbortController` 命中 0 处；长文最多 80 次模型请求 | 中途想停停不下，也不知道要跑多久/花多少 |
| 5 | 导出只有 JSON 备份 | `utils/export.ts` 仅 `validateBackup` 等备份能力 | 卡片无法迁移到 Anki，资料无法交付为 Markdown |
| 6 | 无键盘快捷键 | 全仓 `keydown` 命中 0 处 | 桌面端学习效率低（翻卡只能点鼠标） |
| 7 | 无深色模式 | `dark:` 前缀命中 0 处 | 夜间学习刺眼 |
| 8 | 移动端层级深 | `AppSidebar.vue` 抽屉 + `CompanionWidget.vue` 悬浮球；无底部导航 | 每次切页要开抽屉，悬浮球遮挡内容 |
| 9 | 无骨架屏 | `skeleton` 命中 0 处 | 弱网下只有空白/转圈，观感差 |
| 10 | 可访问性缺失 | `aria-` 命中 0 处；`ConfirmDialog.vue` 无 focus trap | 键盘/读屏用户无法完成关键操作 |
| 11 | 无全局错误兜底 | `app.config.errorHandler` / `onErrorCaptured` 命中 0 处 | 任意运行时异常直接白屏 |
| 12 | 无离线能力（网页版） | `serviceWorker` / `workbox` 命中 0 处 | 断网即废；小工具包反而能离线，能力不对等 |
| 13 | 测试无框架 | 仅 `scripts/` 下 4 个自研冒烟脚本 | 重构缺回归保护 |

### 1.3 保持不动（现有优势）

- 语音输入双通道 + UA 引导 + 点按/按住双模式（`composables/useVoiceInput.ts`）
- 卡片生成固定小段循环 + 三级降级 + 宽松解析（`services/ai/aiService.ts`、`OpenAICompatibleProvider.ts`）
- 小工具离线包（替身模块 + 审计脚本全绿）
- 小知 function calling 与好感度体系（`services/companion/`）

以上模块本次**只做兼容性适配，不改交互语义**。

## 2. 目标与非目标

### 2.1 目标

1. 让「标记掌握度」真正产生后续行为：每天有明确的复习队列，卡片按记忆规律回落。
2. 让资料规模可管理：批量操作 + 跨模块全局搜索。
3. 让 AI 长任务可控：可预估、可中断、已完成结果不丢。
4. 补齐桌面与移动端的操作效率与观感：快捷键、底部导航、深色模式、骨架屏、无障碍。
5. 提升工程韧性：白屏兜底、可离线、可回归。

### 2.2 非目标（本期不做）

- 多人协作 / 账号体系 / 云同步（涉及后端鉴权与数据合并，单独立项）
- 真实 Anki `.apkg`（需 SQLite 打包，先做 CSV）
- AI 生成的图片/音频卡片
- 小工具端内的语音与联网能力（容器限制，维持现状）
- 全新视觉改版（不做大改版，只做设计系统收口与细节打磨）

## 5. 阶段 A · 学习闭环

### A1 数据模型

`frontend/src/db/database.ts` 扩展 `Flashcard`（保持向后兼容，全部新增字段可选）：

```ts
export interface Flashcard {
  id: string;
  documentId: string;
  question: string;
  answer: string;
  mastery: 0 | 1 | 2;
  reviewCount: number;
  nextReviewAt?: string;
  createdAt: string;

  // —— v3 新增（SRS）——
  ease?: number;          // 难度因子，初始 2.5，范围 1.3~3.0
  intervalDays?: number;  // 当前间隔天数，初始 0
  lapses?: number;        // 遗忘次数（答错累计）
  lastReviewedAt?: string;// 上次复习时间，用于「今日已复习」统计
  suspended?: boolean;    // 暂停复习（用户手动归档）
}
```

数据库升级（Dexie v3）：

```ts
this.version(3).stores({
  documents: "id, title, categoryId, favorite, createdAt, updatedAt, *tags",
  categories: "id, name, sortOrder",
  tasks: "id, status, priority, dueDate, sourceDocumentId, createdAt",
  flashcards: "id, documentId, mastery, nextReviewAt, lastReviewedAt, suspended",
  aiJobs: "id, documentId, type, status, createdAt"
});
```

迁移策略：`version(3).upgrade()` 中为历史卡片补 `ease=2.5 / intervalDays=0 / lapses=0`；`reviewCount>0` 但无 `nextReviewAt` 的卡片按 `createdAt + 1 天` 补齐，避免升级后全部涌入「今日待复习」。

### A2 调度算法（简化 SM-2）

`frontend/src/services/flashcardService.ts` 新增：

```ts
export type Rating = 0 | 1 | 2; // 生疏 / 一般 / 掌握 → 映射 quality 1 / 3 / 5

export interface Sm2Result { ease: number; intervalDays: number; lapses: number; nextReviewAt: string; }

export function schedule(card: Flashcard, rating: Rating, now = new Date()): Sm2Result;
```

规则（`quality = [1, 3, 5][rating]`）：

| 情况 | 处理 |
| --- | --- |
| `quality < 3`（生疏） | `lapses+1`；`intervalDays = 0`；`nextReviewAt = now + 10 分钟`（当天再次出现）；`ease = max(1.3, ease - 0.2)` |
| 前两次答对 | 第 1 次 `intervalDays=1`，第 2 次 `intervalDays=3` |
| 之后答对 | `intervalDays = round(intervalDays * ease)`，上限 180 天 |
| `quality === 3`（一般） | `ease = max(1.3, ease - 0.05)`（轻微下调） |
| `quality === 5`（掌握） | `ease = min(3.0, ease + 0.1)` |
| 上限保护 | `nextReviewAt` 不超过 `now + 180 天`；`intervalDays` 至少 1 |

`mastery` 仍保留用于 UI 展示与筛选，取值随 `rating` 同步；`markMastery` 内部改为调用 `schedule()`（对外签名不变，避免影响 `StudyPage.vue` 现有调用）。

### A3 队列查询与入口

新增查询（`flashcardService.ts`）：

```ts
export interface DueBuckets { due: Flashcard[]; overdue: Flashcard[]; todayDoneCount: number; }

export async function listDueCards(now = new Date()): Promise<DueBuckets>;
```

规则：`suspended !== true`、`nextReviewAt <= now` 计入 `due`；其中 `nextReviewAt < 今日 00:00` 计入 `overdue`；`lastReviewedAt >= 今日 00:00` 计入 `todayDoneCount`。

三个入口：

1. **首页行动卡**（`pages/HomePage.vue`）：今日待复习 N 张 / 逾期 M 张，点击直达 `/study?mode=review`。
2. **侧边栏 badge**（`components/AppSidebar.vue`）：「学习中心」右侧小圆点显示 `due + overdue`，为 0 时不显示。
3. **学习中心默认模式**（`pages/StudyPage.vue`）：进入即复习队列；顶部切换「复习队列 / 全部卡片」，URL 参数 `mode=review|all` 持久化。

### A4 学习中心改造

| 改动 | 说明 |
| --- | --- |
| 队列模式 | 按 `nextReviewAt` 升序；答完一张自动移除，队列清空显示完成态（含今日已复习数） |
| 进度条 | 顶部细进度条 + 「第 3 / 26 张」；点击可跳转列表视图 |
| 键盘快捷键 | `←/→` 上下一张，`空格` 翻面，`1/2/3` 标记；输入框聚焦时禁用 |
| 卡片信息 | 显示 `已复习 N 次 · 下次复习 3 天后`；`悬浮显示`来源资料标题（复用 `gotoSource`） |
| 暂停复习 | 卡片菜单加「暂停/恢复」，写 `suspended` |

### A5 验收用例

| 用例 | 期望 |
| --- | --- |
| 标记「生疏」 | 卡片当天再次进入队列，`lapses+1`，`ease` 下降不小于 1.3 |
| 连续标记「掌握」3 次 | 间隔依次 1 → 3 → 8 天（ease 2.5→2.6→2.7，取整） |
| 队列清空 | 显示「今天复习完啦」+ 今日已复习数量 |
| 无卡片 | 空状态引导「去资料详情生成卡片」 |
| 升级迁移 | 旧数据升级后 `ease=2.5`，无卡片因缺 `nextReviewAt` 被忽略 |

## 6. 阶段 B · 资料管理效率

### B1 多选批量

`pages/LibraryPage.vue` 增加「选择模式」：

- 进入方式：长按卡片 或 顶部「选择」按钮；退出保留滚动位置。
- 选中态：卡片左上角复选框；底部浮条显示「已选 3 项」+ 操作按钮。
- 操作：批量删除、批量改分类、批量生成卡片、批量导出 Markdown、取消选择。
- 删除撤销：删除后 5 秒内底部提示「已删除 3 份资料 · 撤销」，撤销从 `documentStore` 快照恢复（内存快照，不写库）。

```ts
// stores/documentStore.ts
bulkRemove(ids: string[]): Promise<void>;
bulkUpdateCategory(ids: string[], categoryId: string): Promise<void>;
restoreSnapshot(snapshot: Document[]): Promise<void>;
```

边界：全选仅作用于当前筛选结果；删除前二次确认（>10 条时额外提示条数）；分类被删除时卡片回落到「未分类」。

### B2 批量生成卡片

- 入口：B1 浮条「批量生成卡片」；弹窗显示「共 N 份资料，预计 M 张卡片」，可取消。
- 执行：复用 `generateCardsFromContent`（已支持分段与重试），逐份串行，显示「第 2/5 份 · 已生成 12 张」。
- 失败隔离：单份失败跳过并记录，结束时汇总「成功 4 份 / 失败 1 份」。
- 结果去重：跨资料按「问题归一化」去重（复用 `aiService` 内部逻辑，导出为公共函数）。
- 写入：进入 AI 工作台的待确认列表太打断流程，批量场景改为**直接落库**并在完成提示中提供「查看卡片」链接（与单篇流程区分，需在文档中标注）。

## 7. 阶段 C · 全局搜索（⌘K）

### C1 索引扩展

`services/searchService.ts` 新增：

```ts
export type SearchKind = "document" | "card" | "task";
export interface GlobalHit { kind: SearchKind; id: string; title: string; excerpt: string; score: number; extra?: string; }

export function searchAll(query: string, data: { documents: Document[]; cards: Flashcard[]; tasks: Task[] }, limit = 20): GlobalHit[];
```

- 复用现有中文 n-gram 分词与打分（文档）；卡片按 `question` 主权重 + `answer` 次权重；任务按 `title` + `description`。

### C2 面板

- 唤出：`⌘K` / `Ctrl+K` 全局；资料库内 `/` 聚焦。

### C3 跳转

## 8. 阶段 D · AI 任务可控

### D1 中断贯通


捕获 `AbortError` 后：**不抛错**，返回已生成部分；`runJob` 将任务状态写为 `canceled`（`AIJobStatus` 增加 `"canceled"`，`types/ai.ts` 同步）。

### D2 预估与进度

- 预估：`estimateCards(contentLength, count)` 返回 `{ chunks, estimatedCards, estimatedCalls }`，在「生成卡片」按钮上方显示「约 6 段 / 约 26 张 / 6 次请求」。

- 取消按钮：加载态下「生成中…」替换为「取消」，点击触发 `abort()`；取消后提示「已保留前 N 张」。

### D3 结果落库

取消或部分失败时，已生成卡片写入 `aiJobs.result`，AI 工作台可「恢复上次结果」，避免重复花钱。

## 10. 阶段 F · 视觉、移动端与无障碍

### F1 深色模式

- `tailwind.config` 设 `darkMode: "class"`；`appStore` 增加 `theme: "light" | "dark" | "system"`，持久化并在 `<html>` 上切 `class`。
- 色彩 token 收口：把散落的 `bg-white` / `text-slate-800` 等，在 `assets/main.css` 里补 `dark:` 变体；优先覆盖「卡片 / 面板 / 输入框 / 侧边栏 / 小知面板 / Toast」六类容器。
- 入口：设置页三选一 + 侧边栏底部快捷切换。
- 验收：全页无「白底黑字块」与「黑底黑字」，图表/悬浮球/语音条在深色下对比度 ≥ 4.5:1。

### F2 移动端底部导航

新增 `components/BottomNav.vue`（`lg:hidden`）：

## 14. 发布与回滚

1. 分支：`feat/v2-learning-loop` → 分阶段合并，A/B 先合，C/D 次之，F/G 最后。
2. 数据迁移前：设置页「导出备份」提示升级风险；迁移失败时保留 v2 数据不破坏（Dexie 升级失败会阻断打开，需在迁移函数内 try/catch 并降级为「不写新字段」）。
3. 发布：`npm run build` → 平台发布（`knowflow-ai`）→ 小工具 `build:minitool` + zip 审计 → 提审。
4. 回滚：前端回退上一版本即可；**数据迁移不可逆**，因此 v3 只加字段不改旧字段语义，旧版本读新数据仍可工作（未知字段被忽略）。

## 15. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 迁移导致老用户打不开 | 高 | 迁移函数 try/catch + 只加字段；发布前用真实旧数据演练 |
| 深色模式遗漏页面 | 中 | 先做 token 收口，再用清单逐页验收（9 个页面 + 小知 + Toast） |
| PWA 缓存导致「更新不生效」 | 中 | `autoUpdate` + 版本提示条 + 提供「强制刷新」入口 |
| 批量生成消耗额度 | 中 | 弹窗预估张数与请求次数；默认上限 3 份资料/次 |
| 队列口径与用户直觉不一致 | 中 | 明确「今日待复习」= `nextReviewAt <= 现在`；逾期单列，避免数字虚高 |
| minitool 构建被新依赖污染 | 中 | CI 中保留「fetch/getUserMedia 计数为 0」检查；新增依赖先过 minitool 构建 |

## 18. 附录 · 术语

| 术语 | 含义 |
| --- | --- |
| SRS | Spaced Repetition System，间隔重复系统 |
| SM-2 | 经典间隔重复算法（SuperMemo 2），本方案为其简化版 |
| ease | 难度因子，控制间隔增长倍率 |
| 逾期 | `nextReviewAt` 早于今日 00:00 的卡片 |
| 队列模式 | 学习中心按 `nextReviewAt` 排序的复习流程，区别于「全部卡片」浏览 |
| 冒烟脚本 | `frontend/scripts/` 下的 `test:render/voice/cards/provider` |
