## 一、背景

### 1.1 现状：两个页面都是「陈列柜」

| 页面 | 现在能做什么 | 缺什么 |
| --- | --- | --- |
| 成语学习 `/study/idiom` | 关键词搜索 + 逐条「加入复习」 | 无法按首字/字数筛、没有掌握度、看不到自己在游戏里错过哪条、不能自建 |
| 饮食 · 食谱 `/kitchen` | 121 道菜列表 + 详情（材料/步骤） | 材料清单大面积缺失、不能筛选（时长/口味/主料）、不能收藏 |
| 饮食 · 计划 `/kitchen/plan` | 自动生成一周/四周 + 只读购物清单 | 只能整周重抽、清单不能勾选/导出 |
| 饮食 · 时令 `/kitchen/season` | 四季蔬果列表 | 只有四季粒度，冬季 40 种挤一起等于没筛 |

### 1.2 一个必须先修的数据硬伤

`frontend/public/packs/recipes.json` 共 121 道，**102 道（84%）的 `materials` 是空数组**，只有做法文字：

```
{"id":"r1","name":"双色萝卜丝","meal":"lunch","materials":[],"steps":["白萝卜丝腌1小时，胡萝卜丝等量……"]}
```

而「购物清单」「本周食材构成」「食材 ↔ 菜谱反查」全部依赖 `materials`。
也就是说这三块功能现在只有 19 道菜在撑，**这才是「不实用」的根，不是界面问题**。

好在原始素材里材料是写着的（`data/食谱/健康菜谱.txt` 的正文有「番茄、黄瓜、菠菜切片」这类表述），
可以从做法文字里抽取 + 人工抽查，不需要新买数据。

### 1.3 判断

「更灵活」不是再加内容，而是让内容能被**标记、修改、带走**：

```
读（现状） → 找（筛选/反查） → 用（冰箱→菜、清单→采购） → 带走（导出）
```

本迭代把两个页面从「读」推到「找」和「用」，自建与编辑（「带走」之后的长期能力）留到下一版。

## 二、目标与非目标

### 2.1 目标

1. **数据先修**：菜谱材料清单从 19 道补到 ≥100 道，且抽取过程可复跑、可校验。
2. **成语能找**：首字 / 尾字 / 字数 / 释义四维筛选，且筛选状态可分享（URL 带参）。
3. **成语能标**：三档掌握度（会 / 模糊 / 不会）直接驱动现有 SRS，不再「一按了之」。
4. **饮食能用**：勾选家里现有食材 → 反查能做的菜；购物清单可勾选、分组、一键复制。
5. **计划能改**：单餐「换这道」+ 锁定某道菜，而不是整周重抽。

### 2.2 非目标

| 不做 | 原因 |
| --- | --- |
| 营养 / 热量合计 | 菜谱只写「适量」，没有份量，算出来是假数字。要做得先有份量数据 |
| 成语例句、近反义 | 数据没有；AI 现生成再当权威释义，出错比没有更糟 |
| 给两个页面加 AI 输入框 | 会变成两个聊天窗口，结构化数据被稀释 |
| 多人协作 / 云同步 | 与整体账号体系一致，仍为本地存储 |
| 用户自建菜谱 | 工作量与自建成语同量级，排在 v6 |

## 三、阶段 0：菜谱数据修复（先做，卡着后面所有功能）

### 3.1 做法

1. 写 `frontend/scripts/extract-materials.mjs`：
   - 读 `recipes.json` 的 `steps` 文本；
   - 用食材词表（`ingredients.psv` 的 154 条 name + alias）做最长匹配，抽出候选材料；
   - 过滤调味料（盐/油/糖/酱油/料酒/味精/淀粉等黑名单，与图鉴口径一致）；
   - 输出 `{ id, name, materials[], confidence }`，低置信度单独列出。
2. 人工抽查：只核 `confidence` 低的与材料数 > 10 条的，其余按抽取结果入库。
3. 回写 `recipes.json`（或生成 `recipes.materials.json` 覆盖层，见 3.3）。

### 3.2 验收线

```
有材料的菜谱  ≥ 100 / 121
明显错抽（把「少许」「适量」当材料）  = 0
调味料混入  = 0
```

### 3.3 一个实现选择

不要直接改 `recipes.json`（它是编译产物，下次 `build:packs` 会被覆盖）。
改为在 `frontend/data/food/recipe-materials.psv` 存「菜名 | 材料1,材料2…」，
由 `build-packs.mjs` 合并进产物 —— 和食材图鉴一样走「源表 → 编译」的路子，可复现、可审查。

## 四、阶段 1：成语页（见效快，不依赖数据）

### 4.1 筛选与排序

| 维度 | 说明 |
| --- | --- |
| 首字 / 尾字 | 从 `w` 现算，索引可预生成 |
| 字数 | 3 / 4 / 5+（现有数据以 4 字为主，保留其他长度以便后续扩充） |
| 释义关键词 | 现有能力，保留 |
| 排序 | 默认原序；可切「按错过次数」「按加入时间」 |

筛选状态写进 URL query（`?first=水&len=4`），这样「含水的成语」可以复制给别人。

### 4.2 三档掌握度

复用现有 SRS，不新建机制：

| 档位 | 动作 |
| --- | --- |
| 不会 | `addWordToReview("idiom", word, false)` + 首轮间隔设为最短 |
| 模糊 | 同上，但排在队尾 |
| 会 | 标记为已掌握，不进队列；可在「已掌握」筛选里回看与撤销 |

状态存 `knowflow.idiom.level`：`{ [成语]: "known" | "fuzzy" | "unknown" }`。

### 4.3 与游戏成绩打通

成语填空每局记录了 `wrongWords`，但成语页看不到。加一列「错过 N 次」+ 一个「只看错过的」开关。
数据来源：`knowflow.game.progress` 里 idiom 的历史错词（需确认是否已持久化，若只在单局内，则加一个累计计数）。

### 4.4 自建成语（本期可延后）

- 存 `knowflow.idiom.custom`，列表里单独分区「我的」，带「编辑 / 删除」；
- 不与内置包混排，避免自建内容污染搜索与筛选结果；
- 自建条目也能加入复习，卡片来源标「自建」。

### 4.5 验收用例

1. 搜「水」→ 首字筛选「水」→ 结果条数与脚本统计一致；
2. 点「不会」→ 学习中心复习队列里出现该成语；
3. 点「会」→ 不出现在队列，且「已掌握」里能看到、可撤销；
4. 成语填空错 2 次 → 成语页该条显示「错过 2 次」，开「只看错过的」只剩它；
5. 筛完状态复制 URL 到新标签页 → 筛选条件还原。

## 五、阶段 2：饮食页（先修数据，再做功能）

### 5.1 冰箱反查（本期最实用的一条）

交互：`/kitchen` 顶部加「我有这些食材」入口 → 弹层里按分类勾选（复用图鉴的分类 chips）→
出结果：**能做的菜（材料全齐）/ 差一两样的菜（缺什么列出来）**。

实现：`materials` 建倒排索引（材料 → 菜 id 列表），勾选集合求交；差集 ≤ 2 的进第二组。

### 5.2 购物清单：勾选、分组、带走

| 能力 | 说明 |
| --- | --- |
| 勾选 | 点一下划掉，状态存本地（按周次隔离，换周自动清） |
| 分组 | 按图鉴分类（蔬菜 / 肉蛋 / 水产 / 豆谷 / 调料）折叠展示 |
| 带走 | 「复制清单」按钮 → 纯文本（`□ 番茄 ×2`），粘到微信/备忘录 |

> 导出比任何新功能都实用 —— 用户真正的动作是「拿着手机去超市」。

### 5.3 计划单餐编辑

| 现在 | 改成 |
| --- | --- |
| 只有「换一换」（整周重抽） | 每餐「换这道」（只换这一格）+ 锁定（锁了不被重抽覆盖） |
| 生成即固定 | 手动加/删某餐的菜 |

锁定状态存 `knowflow.kitchen.locks`（按周次），换周重置。

### 5.4 时令按月

前提：确认素材《超全一年四季时令蔬菜水果表》PDF 是否含月份粒度。
- 含 → 抽成 `data/food/season-months.psv`，页面加「按月」开关，默认当月；
- 不含 → 保持四季，但把冬季 40 种按「耐储 / 叶菜 / 根茎」再分组，别一屏堆完。

### 5.5 食材「一份约多少克」（可选）

在食材详情加「常见一份 ≈ 150g」参考值，用户可自己乘营养值。
标注「参考值，非称重」，且**不参与任何自动计算** —— 一旦参与就等于承认菜谱有份量。

### 5.6 验收用例

1. 勾「番茄 + 鸡蛋」→ 出番茄炒蛋类菜；缺两样的排在后面并标出缺什么；
2. 购物清单勾掉 3 项 → 刷新后仍划掉；换到下一周 → 全部恢复未勾；
3. 点「复制清单」→ 剪贴板是纯文本且带数量；
4. 锁一道菜后点「换一换」→ 那道菜不动；
5. 单餐「换这道」→ 只有那一格变，其余不动。

## 九、风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 材料抽取准确率低 | 购物清单多出「少许」这类假材料 | 黑名单 + 低置信度人工过一遍 + `test:packs` 加断言 |
| 掌握度与 SRS 双写不一致 | 标了「会」却还在队列里 | 「会」直接标记 SRS 为已掌握，不新增字段双写 |
| 计划锁定与周次错位 | 跨周后锁住了上週的菜 | 锁按「周起始日」存，换周自动清 |
| 筛选条件写进 URL 后与词库切换冲突 | 切词库时条件残留 | 词库切换时清 query |
| 抽材料改动 `recipes.json` 被下次构建覆盖 | 数据丢失 | 只存源表，编译时合并 |
